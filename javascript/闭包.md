## 1. 定义与心智模型

### 1.1 一句话

**闭包 = 函数 + 函数创建时能访问到的外层词法环境（变量绑定）。**

内层函数「记住」定义处外层作用域里的变量；即使外层函数已经 `return` 结束，只要内层函数仍被引用，相关外层绑定就可能被引擎保留。

### 1.2 四句话心法（建议背熟）

1. **在哪定义**决定能看见哪些外层变量（词法作用域），与**在哪调用**无关。
2. 闭包捕获的是 **绑定（binding）**，不是某个瞬间的 **值快照**（除非你在闭包里用常量等方式固化）。
3. **`outer()` 每调用一次**，通常多一份独立的局部环境（如各自的 `n`）。
4. **`this` 与闭包是两条轨道**：前者多由调用方式决定；箭头函数没有自己的 `this`。

### 1.3 抽屉比喻

- **每次 `make()` 调用** → 新开一排「抽屉」，里面有一份局部变量（如 `n`）。
- **返回的内层函数** → 带着「去第几排抽屉取东西」的名牌。
- **`a` 和 `b` 若来自两次 `make()`** → 外形相同的行为，但**不是同一排抽屉**。
- **`const b = a`** → 同一把钥匙，**同一排抽屉**。

## 2. 词法作用域与执行上下文

### 2.1 词法作用域（Lexical Scope）

函数在**书写位置**决定能访问哪些外层变量，而不是在**调用位置**决定。JavaScript 是词法作用域，不是动态作用域。

### 2.2 引擎视角（简化模型）

1. 外层函数被调用 → 创建函数执行上下文，建立局部绑定（参数、`let`/`const`/`var` 等）。
2. 内层函数在该上下文中创建 → 关联外层词法环境（规范中可理解为 `[[Environment]]`）。
3. 外层返回内层 → 外层栈帧可结束；若内层仍被引用，**被内层用到的外层绑定**可能继续存活。

要点：并非外层所有变量都会永久保留；未被任何可达闭包引用的，可被 GC 回收（引擎还会做逃逸分析优化）。

### 2.3 读槽，不是拷贝快照

```javascript
function outer() {
  let x = 1;
  const a = () => x;
  x = 2;
  return a;
}
outer()(); // 2 — 读的是绑定 x 的当前值
```

## 3. 核心辨析：几个绑定、几份状态

### 3.1 两次工厂 → 两份状态

```javascript
function make() {
  let n = 0;
  return () => ++n;
}
const a = make();
const b = make();
// a、b：行为相同，但不是同一个函数对象（a !== b）
// 各自闭包里的 n 是两次 make() 的两份独立绑定
```

| 维度 | `a` 与 `b`（两次 `make()`） |
|------|---------------------------|
| 函数引用 | 不同（`a !== b`） |
| 闭包环境 | 两套 |
| 初始 `n` | 都是 0，但**不是同一个变量** |
| 调用后 | 各改各的 `n` |

### 3.2 同一引用 → 一份状态

```javascript
const f = make();
const g = f;
f(); // 1
g(); // 2 — 同一个 n
```

### 3.3 多个函数共享一份状态

```javascript
function pair() {
  let n = 0;
  return {
    inc: () => ++n,
    dec: () => --n,
    read: () => n,
  };
}
const p = pair();
// inc / dec / read 是三个不同函数对象，共用同一次 pair() 里的同一个 n
```

## 4. 循环 + 异步（必考）

### 4.1 先问：这里有几个 `i`？

- **`for (var i …)`**：整个循环（在函数体内则是整个函数作用域）**共享一个 `i` 绑定**。
- **`for (let i …)`**：**每轮迭代**新的块作用域，**新的 `i` 绑定**。

闭包捕获的是**绑定**，不是「循环那一刻的快照值」。

> **`let` 看起来像快照？** 仍是每轮一个新 `i` 绑定；下一轮不会改写上一轮的 `i`，所以异步里常读到 `0, 1, 2`，容易误以为「push 时抄了值」。真快照需 IIFE 参数或 `const` 固化（见 Q12、4.4）。

### 4.2 经典对比

```javascript
// var：异步执行时常看到最终值
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 3, 3, 3

// let：每轮一个新绑定
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 0);
}
// 0, 1, 2
```

### 4.3 什么是 IIFE

**IIFE**（Immediately Invoked Function Expression）= **立即执行函数表达式**：定义一个函数后**马上调用一次**，通常不把它赋给外部变量反复使用。

#### 基本写法

```javascript
(function () {
  console.log('只执行一次');
})();

// 箭头函数版
(() => {
  console.log('只执行一次');
})();
```

外层多包一层 `()`，是为了让引擎把 `function …` 解析成**表达式**（可以紧跟 `()` 调用），而不是单独的函数声明语句。

#### 常见用途

| 场景 | 作用 |
|------|------|
| 隔离作用域 | 内部 `let` 不泄漏到外层（老写法模拟「模块」） |
| `var` 循环 + 异步 | 每轮 IIFE 的参数是新绑定，锁住当时的循环变量 |
| 避免污染全局 | 脚本顶层包一层，少往 `window` 上挂变量（有模块化后较少用） |

#### 与闭包的关系

IIFE **执行完**，外层栈帧可以结束；但若它**内部注册的函数**（如 `setTimeout` 回调）仍存活，那些函数会**闭包**住 IIFE 里的参数或变量。下一节的循环解法就是利用这一点：**每轮调用一次 IIFE，参数 `x` 是该轮独有的绑定**，异步回调各自记住自己的 `x`。

现代循环优先用 `for (let i …)`，效果等价且更直观，IIFE 解法主要用于理解历史代码和面试。

### 4.4 IIFE 解法（理解即可，现代多用 let）

```javascript
for (var k = 0; k < 3; k++) {
  ((x) => {
    setTimeout(() => console.log(x), 0);
  })(k);
}
// 0, 1, 2 — 每轮 IIFE 参数 x 是新绑定
```

## 5. 闭包 vs this

| | 闭包 | `this` |
|---|------|--------|
| 管什么 | 外层词法变量（`let`、参数等） | 通常由**如何调用**函数决定 |
| 箭头函数 | 仍捕获外层变量 | **没有自己的 `this`**，向外层词法找 |

```javascript
const obj = {
  n: 0,
  inc() {
    const inner = () => this.n++;
    inner();
  },
};
obj.inc();
console.log(obj.n); // 1
```

对象方法里 `this` 丢失，与「闭包是否失效」无关，是另一条规则。

## 6. 常见工程模式

| 模式 | 闭包里通常保存什么 |
|------|-------------------|
| 模块 / 私有变量 | 不对外暴露的 `let`、配置 |
| 工厂函数 | 每次调用一份独立状态 |
| 偏函数 / 柯里化 | 已固定的前几个参数 |
| `memoize` | `Map` 缓存 |
| `debounce` / `throttle` | `timer`、上次触发时间 |
| `once` | 是否已执行标志 |

### 6.1 私有计数器

```javascript
function counter(start = 0) {
  let n = start;
  return {
    inc: () => ++n,
    value: () => n,
  };
}
```

### 6.2 柯里化

```javascript
const add = (a) => (b) => a + b;
const add10 = add(10);
add10(3); // 13
```

### 6.3 memoize

```javascript
function memoize(fn) {
  const cache = new Map();
  return (...args) => {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const v = fn(...args);
    cache.set(key, v);
    return v;
  };
}
```

### 6.4 项目开发中的常见场景

日常代码里很少刻意写「闭包」，更多是：**注册回调、返回函数、或模块初始化时，外层变量被内层函数长期引用**。可按下面六类对照排查。

#### 按场景分类

| 类型 | 典型用途 | 闭包里常存什么 | 项目例子 |
|------|----------|----------------|----------|
| 状态封装 | 私有数据、实例隔离 | `let`、配置、内部 API | `createStore`、SDK 客户端、id 生成器 |
| 函数变换 | 不改原函数，加行为 | `timer`、`Map`、执行标志 | 搜索 `debounce`、滚动 `throttle`、计算 `memoize` |
| 事件 / DOM | 回调里要用创建时的上下文 | 索引、配置、元素信息 | 列表点击、拖拽、全局快捷键 |
| 异步回调 | 稍后执行仍要访问当时环境 | 请求参数、重试次数 | `fetch` / `Promise.then`、队列重试 |
| 框架组件 | 渲染或 setup 产生函数，稍后调用 | 某次 render 的 state/props、ref、订阅句柄 | `useEffect` 定时器、自定义 Hook、Vue `setup` |
| 模块 / 架构 | 文件或 bundle 只初始化一次 | 模块顶层变量、中间件配置 | ESM 模块私有变量、Express 中间件、HOC |

#### 按「闭包里存什么」速查

```text
数据：配置、缓存 Map、私有 state
句柄：timer、subscription、AbortController
标志：once、locked、inFlight
函数：被包装的原始 fn（debounce / memoize）
渲染快照：某次 render 的 props / state（React 陈旧闭包）
```

#### 与「几个绑定」的对应

| 项目现象 | 绑定直觉 |
|----------|----------|
| 一次 `debounce()` 返回的函数被连续调用 | **一份** `timer` + `fn` |
| 两个组件各调用一次 `useDebounce` | **两套**独立闭包环境 |
| `useEffect(fn, [])` 里的定时器 | 回调钉在**首次渲染**的那份 state（见 [§9](#9-react陈旧闭包stale-closure)） |
| 循环里 `var` + 绑事件 | **一个** `i`，易出 3,3,3（见 [§4](#4-循环--异步必考)） |

#### 开发注意（比会不会写更重要）

1. **记得清理**：`removeEventListener`、`clearInterval` / `clearTimeout`、取消订阅 / WebSocket，避免闭包长期拽住大对象（见 [§7](#7-浏览器与-dom)、[§11](#11-内存性能与调试)）。
2. **区分「陈旧闭包 bug」与「故意只跑一次」**：`useEffect([], [])` 有时就是要钉住初次配置；若要读最新 state，用依赖数组、`useRef` 或函数式更新（见 [§9](#9-react陈旧闭包stale-closure)）。
3. **闭包里少挂 DOM / 大数组**：只存 `id`，需要时再查。
4. **与 `this` 问题分开看**：对象方法里箭头函数、`setTimeout` 丢 `this` 是另一条规则（见 [§5](#5-闭包-vs-this)）。

## 7. 浏览器与 DOM

- 事件监听回调闭包住创建时的变量；**长期未移除的 listener** 会延长被引用数据的生命周期。
- 组件卸载、路由离开时应：`removeEventListener`、`clearInterval`、取消订阅。
- 避免在闭包中无意保留整棵 DOM 子树或超大列表；必要时只存 `id` 再查询。

## 8. 异步与时间线

- `setTimeout`、`queueMicrotask`、`requestAnimationFrame`、`.then` 的回调都在**稍后**执行。
- 读到的是**回调创建时**闭包里的绑定；若期间外层绑定已变，行为取决于是「共享一个 `var`」还是「每轮新 `let`」。
- **陈旧闭包**：异步回调不会自动「换绑」到最新一次渲染/调用的变量，除非重建回调或借助 ref 等机制。

## 9. React：陈旧闭包（Stale Closure）

### 9.1 现象

函数组件**每次渲染**都会重新执行一遍，产生**新的** `count` 等常量。但 `useEffect(fn, [])` **只在挂载后执行一次** `fn`，其中的 `setInterval` 回调也**只创建一次**，闭包里的 `count` 钉在**第一次渲染**的值上。

```javascript
function Demo() {
  const [count, setCount] = useState(0);
  useEffect(() => {
    const id = setInterval(() => {
      console.log(count); // 依赖 [] 时，往往一直是初次渲染的 count（如 0）
    }, 1000);
    return () => clearInterval(id);
  }, []);
}
```

### 9.2 时间线直觉

| 时刻 | 界面 count | 定时器回调闭包里的 count |
|------|------------|--------------------------|
| 挂载 | 0 | 0（回调在此创建） |
| 用户点到 5 | 5 | 仍可能是 0（同一旧回调） |

### 9.3 常见对策

**方案 A：把变量放进依赖，重建 effect**

```javascript
useEffect(() => {
  const id = setInterval(() => console.log(count), 1000);
  return () => clearInterval(id);
}, [count]); // count 变 → 清旧定时器 → 新回调带新 count
```

缺点：`count` 频繁变化会反复重启定时器。

**方案 B：`useRef` 存最新值，依赖仍为 `[]`**

```javascript
function Demo() {
  const [count, setCount] = useState(0);
  const countRef = useRef(count);
  countRef.current = count;

  useEffect(() => {
    const id = setInterval(() => {
      console.log(countRef.current); // 始终读 .current 上的最新值
    }, 1000);
    return () => clearInterval(id);
  }, []);
}
```

**方案 C：函数式更新，减少对闭包中旧 state 的依赖**

```javascript
setCount((c) => c + 1);
```

### 9.4 一句话

**`[]` = effect 主体只跑一次 → 里面的异步回调也只绑定那一次渲染的变量；后续 state 变了，旧回调不会自动更新，除非重建 effect 或用 ref。**

## 10. Vue 与其他框架要点

- **Composition API**：在 `setup` 里创建的函数闭包的是**该组件实例周期**内的响应式引用；`onUnmounted` 中清理定时器与全局监听。
- **Options API**：注意 `this` 与箭头函数在 methods 中的差异（仍是 `this` 问题，不是闭包定义问题）。
- 小程序 / 跨端：页面销毁时清理闭包可能长期持有的页面对象引用。

## 11. 内存、性能与调试

### 11.1 内存

- 闭包延长「仍被可达引用需要」的外层绑定；不可达会被 GC。
- 泄漏多来自：全局缓存、未清理的 listener / `setInterval`、DevTools 持有大对象引用链。

### 11.2 性能

- 闭包本身通常不是性能原罪；注意闭包数量与被保留数据体积。
- 引擎会对未逃逸变量优化；写作上仍按「被内层引用的外层变量可能随内层存活」来理解。

### 11.3 调试

Chrome DevTools → **Scope** → **Closure** 查看捕获的变量。

## 12. 面试自测题（含答案）

做题时先问三句：**几个绑定？闭包各指向谁？执行那一刻绑定上的值是多少？**

### 12.1 基础题

#### Q1

```javascript
let funcs = [];
for (var i = 0; i < 3; i++) funcs.push(() => i);
funcs.map((f) => f());
```

**答案**：`[3, 3, 3]`。

**几个绑定？** 1 个 `i`（`var`）。三个函数对象不同，但都闭包**同一个** `i`。

**为何不是 `[2, 2, 2]`？** 循环退出前最后一轮还会 `i++`，结束时 `i === 3`；`map` 调用时才读 `i`，不是 push 时的快照。

**为何不是 `[0, 1, 2]`？** 那是 `let` 每轮一个新 `i` 的结果（见 Q5）。

#### Q2

```javascript
function foo() {
  const xs = [];
  for (var i = 0; i < 3; i++) xs.push(() => i);
  return xs.map((f) => f());
}
foo();
```

**答案**：`[3, 3, 3]` — 与 Q1 同类。

#### Q3

```javascript
function outer() {
  let x = 1;
  const a = () => x;
  x = 2;
  return a;
}
outer()();
```

**答案**：`2`。

#### Q4

```javascript
function makeAdder(x) {
  return (y) => x + y;
}
const add5 = makeAdder(5);
console.log(add5(3));
```

**答案**：`8`。

#### Q5（let 版）

将 Q1 中 `var` 改为 `let`：

**答案**：`[0, 1, 2]` — **3 个** `i`（每轮新绑定），不是快照；每轮 `() => i` 各绑各的 `i`。

#### Q6（共享状态）

```javascript
function box() {
  let v = 0;
  return {
    inc: () => ++v,
    read: () => v,
  };
}
const x = box();
const y = box();
x.inc();
x.inc();
console.log(x.read(), y.read());
```

**答案**：`2` 和 `0` — 两套独立 `v`。

### 12.2 循环、异步与 IIFE

#### Q7（`++n`）

```javascript
function create() {
  let n = 0;
  return () => ++n;
}
const f = create();
const g = create();
console.log(f(), f(), g(), g());
```

**答案**：`1, 2, 1, 2` — 两次 `create()` → **2 个** `n`；`++n` 先自增再返回。

#### Q8（`n++`）

同上，仅把 `() => ++n` 改为 `() => n++`。

**答案**：`0, 1, 0, 1` — 绑定份数同 Q7；`n++` 先返回旧值再自增。

#### Q9（`let` + `setTimeout`）

```javascript
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

**答案**：`0, 1, 2`（打印顺序可能交错，数值不变）— **3 个** `i`；延迟不改变闭包指向。

#### Q10（`let` + 双层 `setTimeout`）

```javascript
for (let i = 0; i < 3; i++) {
  setTimeout(() => {
    setTimeout(() => console.log(i), 0);
  }, 0);
}
```

**答案**：`0, 1, 2` — 与 Q9 相同，仍是每轮一个 `i`；嵌套异步**不**把 `let` 变成 `var`。

#### Q11（`var` + 双层 `setTimeout`，对照 Q10）

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    setTimeout(() => console.log(i), 0);
  }, 0);
}
```

**答案**：`3, 3, 3` — **1 个** `i`；内层回调执行时循环已结束，`i === 3`。

#### Q12（`var` + IIFE）

```javascript
const funcs = [];
for (var i = 0; i < 3; i++) {
  (function (x) {
    funcs.push(() => x);
  })(i);
}
console.log(funcs[0](), funcs[1](), funcs[2]());
```

**答案**：`0, 1, 2` — 循环共享 **1 个** `i`，但每轮 IIFE 参数 **x** 是新绑定（共 3 个 `x`）；闭包指向各轮的 `x`，不是最终的 `i`。

#### 循环 + 异步对照表

| 题 | 写法 | 关键绑定 | 结果 |
|----|------|----------|------|
| Q1 / Q2 | `var` + 稍后调用 | 1 个 `i` | `3, 3, 3` |
| Q5 / Q9 / Q10 | `let` + 异步 | 每轮 1 个 `i` | `0, 1, 2` |
| Q11 | `var` + 双层异步 | 1 个 `i` | `3, 3, 3` |
| Q12 | `var` + IIFE(`x`) | 1 个 `i` + 3 个 `x` | `0, 1, 2` |

### 12.3 React 与工程模式

#### Q13（陈旧闭包 · `useEffect([])`）

```javascript
function Counter() {
  const [count, setCount] = useState(0);
  useEffect(() => {
    const id = setInterval(() => console.log(count), 1000);
    return () => clearInterval(id);
  }, []);
  return <button onClick={() => setCount((c) => c + 1)}>+</button>;
}
```

用户把 `count` 点到 5。1 秒、2 秒、3 秒后定时器分别打出？

**答案**：`0, 0, 0` — effect 只跑一次，回调闭包钉在**首次渲染**的 `count`；后续渲染产生新 `count`，旧回调不会自动更新。

#### Q14（哪种能打出最新 count？）

A：`useEffect(..., [])` 闭包旧 `count`。  
B：`useEffect(..., [count])` 每次变就清定时器并重建，闭包带当时 `count`。  
C：`countRef.current = count` + `[]`，回调读 ref 最新值。

**答案**：**B 和 C 都能**在 count 为 3 时打出 3；A 不行。面试若单选「能打出最新」，答 **B** 或 **C** 均可，需说明机制差异。

#### Q15（`debounce` 闭包存什么）

```javascript
function debounce(fn, delay) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}
```

连续快速调用返回函数 5 次，最后一次停下后过 `delay` 毫秒：`fn` 执行几次？闭包长期保存什么？

**答案**：**1 次**；**`timer`** 与 **`fn`**（一次 `debounce()` 调用 → 一份状态，与两次 `create()` 两个 `n` 同型）。
