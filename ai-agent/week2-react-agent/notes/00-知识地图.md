# Week2 知识地图：手写 ReAct Agent

## 本周要建立的脑内模型

```text
Week1 Function Calling
  messages + tools
      ↓
  assistant(tool_calls)
      ↓
  code 执行工具并写回 observation
      ↓
外面套循环
      ↓
ReAct Agent
  直到 assistant 不再返回 tool_calls
```

Week2 的关键是：**协议没有变，结构变了**。从固定两轮，变成模型根据状态动态决定要不要继续调用工具。

## 核心结构

```python
for step in range(max_steps):
    msg = call_llm(messages, tools)
    messages.append(msg)

    if not msg.tool_calls:
        return msg.content

    for call in msg.tool_calls:
        result = dispatch_tool(call)
        messages.append(tool_message(result))
```

## 概念对照

| 概念 | 在代码里是什么 |
| --- | --- |
| State | `messages` |
| Action | `assistant.tool_calls` |
| Tool execution | `dispatch_tool(...)` |
| Observation | `role: tool` 的 `content` |
| Loop | `for step in range(max_steps)` |
| Stop condition | 本轮 assistant 没有 `tool_calls` |
| Safety limit | `max_steps` |

## Agent vs Workflow

| 类型 | 谁决定下一步 | Week2 里怎么体现 |
| --- | --- | --- |
| Workflow | 代码 | 写死先查天气，再计算，再搜索 |
| Agent | 模型 | 模型根据 `messages` 和工具结果决定下一步 |

Week2 学的是 Agent，但工程上仍要记住：能写死的流程，优先 workflow。

## 与 Week3 的关系

Week3 不改变 Agent 语义，只改变组织方式：

```text
Week2 for 循环
  → Week3 agent node + tools node + conditional edge
```

所以 Week2 必须先看懂 `messages` 和退出条件，否则上 LangGraph 只是在学框架 API。
