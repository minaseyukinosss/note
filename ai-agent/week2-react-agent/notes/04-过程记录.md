## Day 8-9：读懂 ReAct 与 Agent 分界

### 学习目标

- 读 Anthropic 的 Building Effective Agents，理解 augmented LLM、workflow、agent 的区别。
- 建立 ReAct 的最小心智模型：模型在循环里决定下一步，代码负责执行工具和维护状态。

### 关键观察

- ReAct 不是 Function Calling 的同义词。Function Calling 是协议，ReAct 是把协议放进循环后的控制结构。
- Workflow 的下一步由代码决定；Agent 的下一步由模型基于当前 state 决定。
- 不是所有“LLM + 工具”都应该叫 Agent。固定步骤能解决时，workflow 更稳定、更容易测试。

### 自测回流

原自测中的高价值错题已经整理为：

| 问题 | 结论 |
| --- | --- |
| augmented LLM 和普通聊天差在哪 | augmented LLM 暴露了工具、检索或记忆能力，但外层不一定有自主循环。 |
| Workflow 和 Agent 谁决定下一步 | Workflow 由代码决定路径；Agent 由模型动态决定下一步。 |
| Week1 Function Calling 和 ReAct 差在哪 | Week1 是固定两轮工具回调；ReAct 是多轮工具回调循环。 |
| 什么情况不该上 Agent | 任务路径清晰、可预测、可测试时，优先 workflow。 |

## Day 10-12：手写 ReAct 循环

### 学习目标

- 跑通 `react_agent.py`。
- 理解 `run_agent` 主循环、工具定义、dispatch、错误 observation。
- 验证天气 + 计算器 + 搜索的多步任务。

### 关键观察

- `messages` 是唯一状态，`assistant(tool_calls)` 和 `tool` observation 都必须按顺序追加。
- `max_steps` 是安全上限，不是正常结束条件。正常结束条件是模型不再返回 `tool_calls`。
- 一轮可能出现多个 `tool_calls`，每个工具结果都要带对应的 `tool_call_id` 写回。
- 工具异常不要直接让程序崩掉，应转成 observation，让模型决定重试或解释失败。

### 代码心智模型

```text
user input
  -> model decides tool_calls
  -> code dispatches tools
  -> tool observations append to messages
  -> model decides again
  -> no tool_calls means final answer
```

## Day 13-14：主动制造失败

### 学习目标

- 故意测试无工具、工具异常、步数不足、模型跳过工具等情况。
- 明确框架能帮什么，不能帮什么。

### 关键观察

- 模型可能心算跳过 calculator，这不是框架能天然解决的问题。
- 无合适工具时，Agent 应该承认能力边界，而不是编造执行结果。
- prompt、工具描述、工具权限、eval 用例要一起管理，单改 prompt 很容易治标不治本。

### 复盘结论

手写 ReAct 的价值在于看清 Agent 的本质：不是“模型更聪明”，而是应用代码把模型决策、工具执行、状态更新组织成一个可观察的循环。进入 Week3 前，应该带着明确问题去看 LangGraph：它如何表达 state、node、edge、checkpointer，而不是期待它自动消除模型的不确定性。
