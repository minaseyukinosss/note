# Week1 实验与踩坑

## 实验 1：改 system prompt

做法：在 `hello.py` 或 `chat.py` 里修改 system prompt。

观察：

- 回答语气是否变化。
- 输出格式是否更稳定。
- prompt 越长，prompt token 是否增加。

结论：system 是输入内容的一部分，不是隐藏配置；它也会占 token。

## 实验 2：`/clear` 后追问

做法：

1. 在 `chat.py` 里先问“我叫小明”。
2. 再问“我叫什么？”
3. 输入 `/clear`。
4. 再问“我叫什么？”

观察：`/clear` 后模型无法可靠回答。

结论：多轮对话靠 `messages`，不是 API 保存了会话。

## 实验 3：temperature 对比

做法：

- `/temp 0` 后问同一个开放问题两次。
- `/temp 1.2` 后问同一个开放问题两次。

观察：temperature 越高，回答越多样，也更可能不稳定。

结论：temperature 管采样随机性，不管记忆，也不改变工具能力。

## 实验 4：工具 description 写差

做法：把 `get_weather` 的 description 改得含糊，比如“一个函数”。

观察：模型更可能不调用工具，或参数填得不稳定。

结论：工具 description 是模型选工具的主要依据，要像给同事写 API 文档一样写。

## 常见报错

| 现象 | 排查 |
| --- | --- |
| `OPENAI_API_KEY` 未找到 | 是否复制并填写 `ai-agent/.env` |
| DeepSeek 鉴权失败 | `OPENAI_BASE_URL`、`OPENAI_MODEL` 是否匹配 |
| 第二轮工具结果无效 | 是否 append 了 `role: tool` |
| API 报 tool message 错 | `tool_call_id` 是否对应上一条 assistant 的 call id |
| token 异常上涨 | 是否把完整历史一直 append，没有清理 |

## 排错顺序

1. 打印完整 `messages`。
2. 看 assistant 是否返回 `tool_calls`。
3. 看 `arguments` 是否是合法 JSON。
4. 看 `dispatch_tool` 是否找到对应函数。
5. 看 `tool` 消息是否带正确 `tool_call_id`。
