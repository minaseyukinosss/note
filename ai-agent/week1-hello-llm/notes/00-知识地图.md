# Week1 知识地图：LLM 调用与工具协议

## 本周要建立的脑内模型

```text
Chat API
  ├─ messages：你给模型看的全部上下文
  ├─ roles：system / user / assistant / tool
  ├─ token：计费与上下文长度单位
  └─ tools：给模型看的工具 schema
        ↓
Function Calling
  assistant(tool_calls)
        ↓
你的代码执行真实函数
        ↓
tool observation 写回 messages
        ↓
assistant(content) 生成最终回答
```

Week1 的核心不是 Agent，而是 **协议**：模型不会保存状态，也不会执行函数；状态维护和工具执行都在应用代码里。

## 必须分清的边界

| 问题 | 正确认知 |
| --- | --- |
| 模型记得上一轮吗？ | 不记得。你每轮把历史 `messages` 重发给它。 |
| 模型会执行 Python 函数吗？ | 不会。它只输出结构化调用意图。 |
| `tools` 是给谁看的？ | 给模型看的 API 文档。 |
| `dispatch_tool` 是干什么的？ | 应用侧执行真实函数，并把结果转成 observation。 |
| `role: tool` 是什么？ | 工具结果，不是用户输入，也不是模型回答。 |

## 与 Week2 的关系

Week1 是固定两轮：

```text
模型选工具 → 代码执行 → 模型总结
```

Week2 会把它放进循环：

```text
模型选工具 → 代码执行 → 模型再判断 → ... → 最终回答
```

这就是最小 ReAct Agent 的地基。
