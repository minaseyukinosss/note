# Week1 每日任务

## Day 1-2：第一次 LLM 调用

**目标**：跑通最小请求，理解 `system` / `user` / `assistant` 与 token。

```bash
cd ai-agent
source .venv/bin/activate
python week1-hello-llm/code/hello.py
```

观察：

- 终端是否打印模型回答。
- `usage.prompt_tokens`、`completion_tokens`、`total_tokens` 分别是多少。
- 改 system prompt 后，回答风格是否变化。
- 是否能复述这次请求的输入、输出和 token 成本。

记录：

- `system` / `user` / `assistant` 分别是谁在说话？
- 为什么 system prompt 也算 prompt token？
- token 和字数有什么区别？

详细记录统一整理在 [04-过程记录](./04-过程记录.md#day-1-2第一次-llm-调用)。

## Day 3-4：多轮对话

**目标**：理解 `messages` 如何在应用侧累积。

```bash
cd ai-agent
source .venv/bin/activate
python week1-hello-llm/code/chat.py
```

实验：

- 连续问两轮，让第二轮引用第一轮内容。
- 输入 `/clear`，再问上一轮相关问题。
- 用 `/temp 0` 和 `/temp 1.2` 对比稳定性。
- 可选：在初始化 `messages` 里加入 few-shot 示例。

记录：

- 第二轮请求前，`messages` 里有哪些 role？
- 为什么聊越久 token 越多？
- system 和 temperature 分别影响什么？

详细记录统一整理在 [04-过程记录](./04-过程记录.md#day-3-4多轮对话)。

## Day 5-7：Function Calling

**目标**：跑通“模型选工具 → 代码执行 → 模型总结”的两轮协议。

```bash
cd ai-agent
source .venv/bin/activate
python week1-hello-llm/code/function_calling_demo.py
```

观察：

- 第一轮 assistant 是否返回 `tool_calls`。
- `function.name` 和 `function.arguments` 是什么。
- 代码如何 dispatch 到真实函数。
- 第二轮为什么要加入 `role: tool`。
- 工具 observation 是否足够清楚，模型能否基于它生成最终回答。

记录：

- LLM 调用工具的本质是什么？
- `tools` schema 和真实 Python 函数如何对齐？
- 如果工具执行失败，应如何把错误返回给模型？

详细记录统一整理在 [04-过程记录](./04-过程记录.md#day-5-7function-calling)。
