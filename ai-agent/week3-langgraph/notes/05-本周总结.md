# Week3 总结：LangGraph + 真工具 + 可交付 Demo

## 本周目标

- 用 LangGraph 重写 Week2 的 ReAct Agent，建立 state / node / edge 的工程视角。
- 接入真实工具或本地文件能力，让 Agent 能接触外部世界。
- 用 Checkpointer 和 trace 把 Demo 做到可续聊、可观察、可排错。

## 本周脉络

```text
Day 15-16
    手写 ReAct → LangGraph StateGraph
Day 17-19
    真工具 + checkpoint：接外部世界，保存 state
Day 20-21
    Demo 交付：README、示例对话、trace
```

## 核心收获

1. **LangGraph 是组织方式，不是新脑子**：模型、prompt、工具不变时，行为大体仍和手写版一致。
2. **State 是系统的事实来源**：本仓库主要是 `messages`；后续可以扩展任务状态、用户偏好、工具结果缓存。
3. **Node 是可观测的步骤**：`agent` 调模型，`tools` 执行工具；拆成节点后更容易 trace 和恢复。
4. **Edge 表达控制流**：有 `tool_calls` 走工具，无 `tool_calls` 结束；这对应 Week2 的退出判断。
5. **Checkpointer 存的是 state 快照**：同一 `thread_id` 续聊；换 `thread_id` 就是另一段会话。
6. **真工具带来真风险**：搜索有延迟和不可信内容，读文件有路径权限，写操作需要人工确认或 dry-run。
7. **交付不是多写功能**：README、示例、失败用例、trace，决定别人能不能理解和复现你的 Agent。

## 验收自测

1. **State / node / edge 分别是什么？**  
   State 是流转数据；node 是一步操作；edge 决定下一步去哪。

2. **LangGraph 比手写版多解决了什么？**  
   图结构、状态合并、工具节点、checkpoint、trace 接入更自然。

3. **它没解决什么？**  
   模型乱选工具、心算跳过工具、外部内容不可信、任务本身是否答对。

4. **Checkpoint 和长期记忆一样吗？**  
   不一样。Checkpoint 是保存某条会话的 state 快照；长期记忆还涉及写入策略、检索、更新、遗忘和权限。

5. **trace 能帮你定位什么？**  
   哪一步调了哪个工具、参数是什么、observation 是什么、最终从哪一步开始偏。

## 三周后的位置

到 Week3 结束，你应该已经能从零解释并实现一个最小 Agent：

```text
messages state
  → LLM 产生 tool_calls
  → code 执行工具
  → observation 写回 state
  → 循环直到最终回答
```

下一阶段建议按优先级走：

1. **RAG / 私有知识库**：把 search 换成自己的文档检索，并要求回答带引用。
2. **评估集**：做 20-50 条 golden case，记录任务完成率、工具选择准确率、成本和延迟。
3. **安全边界**：给读写文件、发请求、执行代码等高权限工具加白名单、dry-run 和人工确认。

先把单 Agent 的 trace、eval、权限边界做好，再考虑多 Agent。
