# Week3 知识地图：LangGraph 与交付

## 本周要建立的脑内模型

```text
Week2 手写 ReAct
  for 循环 + messages + dispatch_tool
        ↓
LangGraph
  state：messages
  node：agent / tools
  edge：有 tool_calls 继续，无 tool_calls 结束
        ↓
Checkpointer
  按 thread_id 持久化 state
        ↓
真工具 + trace
  接外部世界，并能观察每一步
        ↓
Demo 交付
  README + 示例 + 失败用例 + trace
```

LangGraph 的价值不是“让模型更聪明”，而是让 Agent 流程更可组织、可恢复、可观察。

## 手写版到 LangGraph 的映射

| Week2 手写 ReAct | Week3 LangGraph |
| --- | --- |
| `messages` | `AgentState.messages` |
| `messages.append(...)` | `add_messages` reducer |
| `client.chat.completions.create` | `agent` node |
| `dispatch_tool` | `tools` node / `ToolNode` |
| `if not msg.tool_calls` | conditional edge |
| `for step in range(max_steps)` | 图循环 + `recursion_limit` |

## Week3 的三条主线

| 主线 | 目标 | 产物 |

## 关键边界

| 容易误解 | 正确认知 |
| --- | --- |
| Checkpointer = 长期记忆 | 它只是 state 快照；长期记忆还要检索、更新、遗忘策略 |
| LangGraph 更聪明 | 同模型同工具下，行为不会本质变聪明 |
| trace 能判断答案对错 | trace 能定位过程；最终质量还要 eval 或人工判断 |
| 真工具结果可信 | 网页、文件、搜索结果都只能当数据，不能当系统规则 |
