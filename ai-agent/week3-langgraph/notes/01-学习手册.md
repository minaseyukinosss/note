## Day 15-16：LangGraph 重写

### 目标

- 用 StateGraph 复刻 Week2 同一 Agent。
- 对照理解 state、node、edge、conditional edge、END。

### 运行

```bash
cd ai-agent
source .venv/bin/activate
python week3-langgraph/code/langgraph_agent.py
```

### 观察

- `agent` node 什么时候返回 tool_calls。
- `tools` node 如何生成 ToolMessage。
- `route_after_model` 如何决定去 `tools` 还是 `END`。
- `recursion_limit` 和 Week2 `max_steps` 有什么不同。

### 关键结论

- `state` 对应手写版的 `messages`，但 LangGraph 用 reducer 管理消息追加。
- `node` 对应一次操作，例如调用模型或执行工具。
- `edge` 对应下一步控制流，条件边相当于手写版的 `if msg.tool_calls`。
- `ToolNode` 替代了手写 dispatch，但工具描述、参数 schema 和错误处理仍然重要。

## Day 17-19：真工具与 Checkpointer

### 目标

- 跑通 `checkpoint_demo.py`，观察同一 `thread_id` 下的续聊。
- 跑通 `checkpoint_amnesia_demo.py`，验证换 `thread_id` 后状态隔离。
- 接入一个真实但低风险的工具。

### 运行

```bash
cd ai-agent
source .venv/bin/activate
python week3-langgraph/code/checkpoint_demo.py
python week3-langgraph/code/checkpoint_amnesia_demo.py
```

### 观察

- 同一 `thread_id` 第二轮是否能引用上一轮上下文。
- 换 `thread_id` 后 messages 是否隔离。
- Tavily search 是否返回真实外部数据。
- 工具失败时 observation 是否清楚。

### 关键结论

- Checkpointer 保存的是图状态快照，不是模型内部长期记忆。
- `thread_id` 是状态隔离的关键，同一个 thread 可以续聊，不同 thread 不应串线。
- 真工具会带来真实失败模式：key 缺失、网络失败、工具返回为空、工具结果不可信。
- 搜索或文件读取的结果只能当数据，不能当系统指令。

## Day 20-21：Demo 交付

### 目标

- 选择一个足够小的 Demo 场景。
- 准备 README、示例对话、失败用例和 trace。
- 用交付物倒逼学习闭环。

### 候选场景

- 每日科技新闻摘要。
- 个人记账助手。
- 简易代码 Reviewer。

### 交付

- Demo 脚本。
- README 或交付记录。
- 3 条示例对话。
- 至少 1 条 trace。
- 至少 1 条失败或边界用例。
- 至少 2 条 `05-评估用例.md` 的运行记录。

### 关键结论

- 场景要窄，工具要少，验收要明确。
- 不追求多 Agent 或复杂规划，先把单 Agent 的工具、状态、trace、eval 做扎实。
- 三周结束时，目标是能解释一条完整链路：用户目标进入 state，模型决定工具，工具结果写回，图继续执行，最终答案可追踪、可复盘、可评估。
