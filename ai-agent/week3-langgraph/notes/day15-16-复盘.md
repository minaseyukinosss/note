## 核心收获（6 条）

1. **LangGraph 没有新 Agent 逻辑**：手写版用 `for` 循环串起「调模型 → 跑工具」；LangGraph 把同一条路径画成流程图。模型、prompt、工具不变，行为应一致。
2. **State = 传阅的笔记本**：这里就是 `AgentState.messages`；`add_messages` 代替手写 `messages.append(...)`。
3. **Node = 流程图上的框**：本仓库只有两个——`agent`（调 LLM）和 `tools`（`ToolNode` 执行工具）。
4. **Edge = 下一步去哪**：`tools → agent` 是普通边（固定回环）；`agent` 出口是条件边（有/无 `tool_calls`）。
5. **`route_after_model` 不是 node**：它是挂在 `agent` 出口上的路由函数，等价手写版里的 `if not msg.tool_calls: return`；画图时只从 `agent` 画分叉，不必画成单独框。
6. **框架省样板，不省脑子**：仍要看 `messages`、懂退出条件；「心算跳过 calculator」换框架也不会消失。

## 手写 ReAct → LangGraph 对照表

| 手写版 `react_agent.py` | LangGraph | 备注 |
| --- | --- | --- |
| `messages` | `AgentState.messages` | 唯一 state |
| `messages.append(...)` | node 返回 `{"messages": [...]}` + `add_messages` | 框架合并 |
| `for step in range(max_steps)` | `invoke` + `tools→agent` 边 | 框架替你循环 |
| `create(..., tools=TOOLS)` | `call_model` 节点 + `bind_tools` | 调 LLM |
| `dispatch_tool` + `role: tool` | `ToolNode` 节点 | 无手写 dispatch |
| `if not msg.tool_calls: return` | `route_after_model` + 条件边 | 不是 node |
| `max_steps=6` | `recursion_limit=12` | 数的是 node 次数，不是 create 次数 |

## 图结构（含条件边语义）

```text
        ┌─────────┐
 START ─►│  agent  │─── 无 tool_calls ───► END
        └────┬────┘      （route_after_model 判 END）
             │ 有 tool_calls
             ▼
        ┌─────────┐
        │  tools  │
        └────┬────┘
             │ 固定边 add_edge
             └──────────► agent
```

`add_conditional_edges("agent", route_after_model, {"tools": "tools", END: END})` 三参数：

- 参数 1 `"agent"`：分叉挂在 agent 后面。
- 参数 2 `route_after_model`：路由函数，读 state 返回 `"tools"` 或 `END`。
- 参数 3 字典：返回值 → 下一节点名；`"tools"` 对应 `add_node("tools", ...)` 注册的名字。

## 读 Quickstart 的体会

- 前两节（Graph、State）偏 **怎么写 API**，少讲 **为什么要用图**。
- 正确读法：先能在脑子里跑通手写版的 `for` 循环（调模型 → 判 tool_calls → dispatch → 再调模型），再把每一块贴到 node/edge 上。
- 感觉「只是在读代码」是正常的——LangGraph 教的是组织方式，不是新的 Agent 范式。

## 踩过的坑

| 现象 | 原因 / 对策 |
| --- | --- |
| `No module named 'langchain_core'` | 未在主题根 venv 装依赖，或未激活 venv；`cd ai-agent && source .venv/bin/activate && pip install -r requirements.txt`，或用 `.venv/bin/python week3-langgraph/code/langgraph_agent.py` |
| 以为 `route_after_model` 是图上的一框 | 它是条件边的路由函数，不是 node |
| 不懂 `{"tools": "tools"}` | 左 key = 路由函数返回值，右 value = `add_node` 注册的节点名 |
| 以为 LangGraph 更聪明 | 同一模型 + prompt + 工具，行为与手写版应接近 |

## 验收自测（口头能答即过关）

1. **State 是什么？** — `messages`，全程带着走。
2. **有几个 node？** — `agent`、`tools`（外加框架的 START/END）。
3. **循环怎么实现？** — `tools → agent` 固定边 + `graph.invoke`；不用手写 `for`。
4. **`route_after_model` 在哪？** — agent 出口的条件边上，不是 node。
5. **LangGraph 在工程上多提供了什么？** — 用图表达流程、自动合并 messages、ToolNode 省 dispatch 样板；**不**解决模型乱选工具或心算代算。
