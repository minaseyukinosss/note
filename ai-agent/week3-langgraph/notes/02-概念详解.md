# Week3 概念详解

## State

State 是图中每个节点共享和更新的数据。本仓库的核心 state 是：

```python
class AgentState(TypedDict):
    messages: Annotated[list, add_messages]
```

`add_messages` 的作用是把节点返回的新消息合并进旧消息列表，代替 Week2 手写的 `messages.append(...)`。

## Node

Node 是图上的一步操作。本仓库主要两个节点：

| node | 作用 |
| --- | --- |
| `agent` | 调 LLM，返回 AIMessage，可能带 `tool_calls` |
| `tools` | 执行 tool_calls，返回 ToolMessage |

Node 应该尽量职责单一，方便 trace 和排错。

## Edge

Edge 决定下一步去哪。

```text
START → agent
agent --有 tool_calls--> tools
agent --无 tool_calls--> END
tools → agent
```

`route_after_model` 不是 node，而是挂在 `agent` 出口的条件路由函数。

## `recursion_limit`

LangGraph 的 `recursion_limit` 限制的是图节点执行次数，不等同于 Week2 的 `max_steps`。

一次 ReAct 工具轮通常会执行：

```text
agent node → tools node → agent node
```

所以 Week2 的 6 次模型调用，大致可能对应 LangGraph 里的 12 个左右 node step。

## Checkpointer

Checkpointer 会在图执行过程中保存 state 快照。调用时通过 `thread_id` 区分会话：

```python
config={"configurable": {"thread_id": "user-123"}}
```

同一 `thread_id`：续接上一轮 state。  
不同 `thread_id`：互相隔离。

它不是长期记忆系统，只是“这条会话的状态存档”。

## 真工具

真工具让 Agent 接触外部世界，也引入风险：

- 搜索结果可能过期或不可信。
- 文件读取可能越权。
- 写操作可能造成副作用。
- 外部 API 可能失败、超时、收费。

工具设计要包含：

- 清晰 description。
- 参数 schema。
- 错误 observation。
- 权限边界。
- 必要时 human-in-the-loop。

## Trace

Trace 记录过程，不自动证明答案正确。

它适合回答：

- 哪一步调用了模型？
- 模型选了哪个工具？
- 参数是什么？
- 工具返回了什么？
- 延迟和 token 大概花在哪里？

它不适合单独回答：

- 业务答案一定对吗？
- prompt 长期效果更好吗？
- 用户是否满意？

这些需要 eval、golden set 或人工标注。
