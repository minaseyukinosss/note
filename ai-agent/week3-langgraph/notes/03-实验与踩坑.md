# Week3 实验与踩坑

## 实验 1：同一问题跑 Week2 和 Week3

问题：北京天气 + `23 * 47`。

观察：

- 两版是否都能完成。
- 工具调用顺序是否类似。
- LangGraph 是否减少了样板代码。

结论：LangGraph 改变的是工程结构，不是模型能力。

## 实验 2：`recursion_limit` 太小

现象：图可能在完成前中断。

排查：

- 任务需要几轮 tool call。
- 每轮会消耗几个 node step。
- 是否有无效循环。

## 实验 3：同一 `thread_id` 续聊

运行 `checkpoint_demo.py`。

观察：第二轮“那上海呢？”是否能结合上一轮语境。

注意：不要只看最终回答。要看 `messages` 是否真的包含上一轮内容。

## 实验 4：换 `thread_id` 失忆

运行 `checkpoint_amnesia_demo.py`。

观察：换 thread 后，第二轮 messages 里不应包含北京那轮历史。

结论：checkpoint 是按 thread 隔离的 state 快照。

## 实验 5：Tavily Key 缺失

现象：search 工具返回“未配置 TAVILY_API_KEY”。

期望：Agent 应基于错误 observation 告知用户无法搜索，而不是编造实时结果。

## 实验 6：Demo 失败用例

每个 Demo 至少保留一条失败或边界用例，例如：

- 搜索无结果。
- 文件不存在。
- 用户要求执行没有权限的动作。
- 多轮追问缺少上下文。

这比只展示 happy path 更能证明你会排错。

## 常见问题

| 现象 | 原因 / 修正 |
| --- | --- |
| `No module named langgraph` | 没装主题根 `requirements.txt` |
| 图不结束 | 条件边判断错误，或模型持续返回 tool_calls |
| 第二轮失忆 | `thread_id` 变了，或没有 compile checkpointer |
| 搜索失败 | `TAVILY_API_KEY` 缺失或网络/API 失败 |
| trace 看不到工具 | callback 没接到 graph invoke config |

## 排错顺序

1. 看 trace 或打印 state。
2. 确认当前 node 是 `agent` 还是 `tools`。
3. 看最后一条 AIMessage 是否有 `tool_calls`。
4. 看 ToolMessage 内容是否符合预期。
5. 看 `thread_id` 是否正确。
6. 再决定改 graph、prompt、工具或 eval。
