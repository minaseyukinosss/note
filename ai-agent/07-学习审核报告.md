# AI Agent 学习项目审核报告

## 总体结论

当前 `ai-agent/` 已经具备一条清晰、可执行的入门路径：Week1 先理解 LLM 调用与工具协议，Week2 裸写 ReAct 循环，Week3 用 LangGraph 做图编排、checkpoint、trace 和最小交付。这条线是合理的，尤其适合从零开始建立正确心智模型。

从专业 Agent 工程角度看，当前路线已经做过一次校准：不把 RAG、长期记忆、多 Agent 提前塞进入门三周；从 Week2 开始维护 eval；Week3 聚焦可恢复、可观测、可复现。后续重点应放在 Week4 的 RAG / 引用 / 评估项目化落地，而不是继续横向追框架。

## 做得好的地方

1. **学习顺序正确**：没有一上来堆 LangChain / LangGraph，而是先理解 API、messages、tool calls，再进入 ReAct 循环。
2. **每周主线明确**：Week1 是协议，Week2 是循环，Week3 是图结构和持久化，对应 Agent 学习的真实难点。
3. **笔记类型已经成型**：每周固定为 `00-知识地图`、`01-学习手册`、`02-概念详解`、`03-实验与踩坑`、`05-本周总结`。
4. **工程意识较强**：已经覆盖 `max_steps`、错误 observation、checkpointer、trace、eval、Demo 交付等关键点。
5. **避免概念膨胀**：多次强调 workflow 与 agent 的边界，这是学习 Agent 时最容易走偏的地方。

## 主要问题

### 1. 入口文档已有明确分工

`README.md`、`01-小白入门.md`、`02-学习路线.md` 都与路线相关，但面向读者不同：

| 文档 | 角色 |
| --- | --- |
| `README.md` | 总入口，只回答“这个主题怎么读、现在到哪了”。 |
| `01-小白入门.md` | 3 周入门训练营，面向零基础。 |
| `02-学习路线.md` | 8-12 周长期路线，面向继续深入。 |
| `05-评估用例.md` | 跨 week 回归测试集。 |
| `06-笔记整理规范.md` | 后续所有笔记的写法标准。 |
| `07-学习审核报告.md` | 阶段性诊断，说明当前结构是否合理、下一步怎么优化。 |

### 2. 过程笔记已收束，后续要控制新增

原 day notes 已合并进每周 `01-学习手册.md`。后续建议坚持双层结构：

- **沉淀笔记**：知识地图、概念详解、周总结，控制在 50-100 行，给未来复习用。
- **学习手册**：`01-学习手册.md`，学习当天唯一入口，记录真实思考、自测、代码观察和踩坑回流。

### 3. Week4 需要项目化

当前前三周非常扎实，后续不要急着上多 Agent。建议下一步新增 Week4：

```text
Week4-rag-memory
  目标：给 Week3 Agent 增加本地知识库检索工具
  交付：可索引 3-5 篇 markdown，并在回答中返回引用来源
  验收：10-20 条 golden case，记录召回、引用、幻觉情况
```

### 4. 评估意识需要提前进入

评估不应只放到阶段 5。当前已经建立 `05-评估用例.md`，后续每次改 prompt、工具 schema、模型或框架都应更新：

- 输入问题
- 预期工具调用
- 预期最终答案要点
- 实际是否通过
- 失败原因

这样后续改 prompt、换模型、上 LangGraph 时能做回归对比。

### 5. 运行产物需要继续隔离

当前 `.gitignore` 已忽略 `.env`、`.venv`、`__pycache__`、`checkpoints.db`、`checkpoints.db-*` 和 `*.sqlite*`。这类文件不是学习资料，不应进入笔记体系。

## 优化原则

1. **入口少而稳**：总入口不堆细节，只指向该读的文档。
2. **笔记分层**：学习记录可以长，复习沉淀必须短。
3. **每周有验收**：不能只写“学了什么”，要写“能不能跑、能不能解释、能不能复现”。
4. **每阶段有产物**：代码、Demo、测试集、复盘至少有一个能交付。
5. **从 Week2 开始评估**：Agent 的价值不是“能跑一次”，而是“在一组稳定用例上表现可解释”。
6. **先单 Agent 后多 Agent**：单 Agent 的工具、状态、trace、eval 没打牢前，不进入多 Agent。
