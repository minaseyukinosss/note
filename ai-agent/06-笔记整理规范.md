# AI Agent 笔记整理规范

## 目标

让这个目录既能记录学习过程，也能在 1 个月后快速复习，还能继续扩展成可运行项目集。

## 文档分层

每个 week 固定保留 5 类文档：

| 类型 | 文件 | 用途 | 建议长度 |
| --- | --- | --- | --- |
| 知识地图 | `00-知识地图.md` | 一页看清本周概念结构 | 50-80 行 |
| 学习手册 | `01-学习手册.md` | 当天唯一入口：任务、命令、观察点、关键结论和记录区 | 100-180 行 |
| 概念详解 | `02-概念详解.md` | 稳定概念沉淀，供复习查阅 | 60-120 行 |
| 实验与踩坑 | `03-实验与踩坑.md` | 记录失败、排错路径、边界情况 | 50-100 行 |
| 本周总结 | `05-本周总结.md` | 本周结论、验收、自测、下周衔接 | 50-100 行 |

不再新增零散 day notes。当天学习只打开 `01-学习手册.md`；周末再把稳定结论回流到 `02`、`03`、`05`。

## 命名规范

- 周目录：`weekN-topic`，例如 `week4-rag-memory`。
- 根目录通用文档：使用数字前缀，例如 `01-小白入门.md`、`05-评估用例.md`。
- 周内笔记：使用 `00`、`01`、`02`、`03`、`05` 前缀；`01-学习手册.md` 是学习现场唯一入口。
- 过程记录：统一写入 `01-学习手册.md` 的记录区，不再新增 `dayX-*.md` 或 `04-过程记录.md`。
- 总结：统一命名为 `05-本周总结.md`。
- 代码目录只放可运行示例，不放截图、数据库、缓存文件。

## 笔记质量标准

一篇好笔记至少回答 4 个问题：

1. 这个概念解决什么问题？
2. 它和上一个概念有什么区别？
3. 代码里哪一行体现了它？
4. 它失败时通常是什么样？

如果只写“是什么”，没有“怎么验证”和“怎么失败”，这篇笔记还没有完成。

## 复盘规则

每周结束时做一次 20 分钟整理：

1. 把 `01-学习手册.md` 记录区里的稳定结论搬到 `02-概念详解.md`。
2. 把报错、误解、模型异常行为搬到 `03-实验与踩坑.md`。
3. 把 3-5 个最重要问题搬到 `05-本周总结.md` 的自测区。
4. 把固定输入和预期表现搬到 `05-评估用例.md`。
5. 删除或忽略运行产物，不把缓存和数据库旁路文件当学习资料。

## Agent 学习专用检查表

写任何 Agent 相关笔记时，尽量补齐这些字段：

| 字段 | 要回答的问题 |
| --- | --- |
| State | 当前状态存在哪里？是 `messages`、数据库，还是图状态？ |
| Decision | 下一步是谁决定的？代码还是模型？ |
| Tool | 工具有哪些？参数 schema 是否清楚？ |
| Observation | 工具结果如何写回上下文？失败如何表达？ |
| Stop | 什么时候停止？最大步数只是安全上限还是业务条件？ |
| Trace | 出问题时能不能复现完整轨迹？ |
| Eval | 有没有固定输入能回归测试？ |
