## 一、本周做了什么

- 知识库：3 篇 markdown → `MarkdownHeaderTextSplitter` 切 13 chunk → Chroma 本地持久化（`build_index.py`）。
- Agent 接入：`retrieve` 工具 + LangGraph 图（`rag_agent.py`），回答带 `[来源: ...]`，未命中说「知识库中没有相关内容」。
- 评估：W4-001 ~ W4-003 手动跑通并记录到 [`05-评估用例.md`](../../05-评估用例.md)。

## 二、最有价值的认知收获

1. RAG 链路 = 离线建库（切分→嵌入→入库）+ 在线检索（top_k→阈值→生成带引用）；Agent 只是把检索封装成工具。
2. top_k 管「取几条」，阈值管「整批要不要」；LLM 定 query/top_k，Chroma 定相似度排序，代码定阈值过滤。
3. 绝对 cosine 分数在小语料 + 英文 embedding 下不可校准；评估不能只看答案，必须看引用和未命中行为。

## 三、RAG 链路一句话回顾

```text
【离线】markdown → 切分（带 source/section） → embedding → Chroma 向量库
【在线】用户问题 → LLM 调 retrieve(query, top_k)
              → Chroma 取 top_k + top-1 过阈值？
              → hits 作为 tool observation → LLM 带引用回答
```

每一步都有失败模式：切分粒度、embedding 模型选型、top-1 阈值、top_k 不够导致漏召回、模型跳过 retrieve、引用缺失、未命中仍编造。

## 四、与"LangGraph 版"（[`langgraph_agent.py`](../../week3-langgraph/code/langgraph_agent.py)）的衔接

LangGraph 版用 StateGraph 组织了 `agent ↔ tools` 两节点 + 条件边 + checkpoint 持久化，工具是公共服务（天气 mock、计算器、Tavily）。RAG 版没改图结构，只是：

- 多了一个 `retrieve` 工具（私有知识库）。
- System Prompt 增加了"必须引用 / 未命中说不知道 / 外部内容不可信"约束。
- 评估多了一维：引用是否真的支持结论。

如果以后引入"长期记忆"，需要再加一层"读取 + 写回"的状态管理，那时才离开 RAG 范畴，进入 Memory。
