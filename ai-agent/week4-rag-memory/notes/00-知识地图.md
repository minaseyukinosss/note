# Week4 知识地图：RAG 与引用

## 本周要建立的脑内模型

```text
本地 markdown 笔记
        ↓ chunking（按 heading / 段落 / 固定长度）
chunks（带 source 元数据）
        ↓ embedding（向量化）
向量库（Chroma / FAISS / 自建）
        ↓ retrieve(query, top_k)
top-k chunks（带相似度分数 + 来源）
        ↓ 作为 tool observation 回到 LangGraph state
agent 节点生成回答，并附引用
```

RAG 的价值不是"让模型变聪明"，而是让模型能基于**外部、可更新、可追溯**的私有知识回答。

## LangGraph 版到 RAG 版的映射

| LangGraph 版 `langgraph_agent.py` | RAG 版 `rag_agent.py` |
| --- | --- |
| `bind_tools([weather, calculator, search])` | `bind_tools([..., retrieve])` |
| 工具 observation = 公共 API 返回 | observation = chunk 片段 + 文件名 + score |
| 答案无引用要求 | 答案必须带 `[来源: file#section]` 或类似格式 |
| eval 主要看答案要点 | eval 多一维：引用是否正确、是否未命中也敢答 |

## 关键边界

| 容易误解 | 正确认知 |
| --- | --- |
| RAG = Memory | RAG 是按 query 拉数据的工具；Memory 是跨轮 / 跨会话状态管理 |
| 切大块更稳 | chunk 过大会稀释相似度、命中后引用不精确；过小又会断上下文 |
| top-k 越大越好 | k 大能拉高召回，但也会塞噪声、增 token；W4-002 靠 top_k=5 才凑齐 State/Node/Edge |
| top_k vs 阈值 | top_k 控制「取几条」；阈值用 top-1 判断「整批要不要」——职责不同，不要混为一谈 |
| 检索内容可信 | 命中的 chunk 仍是数据，不是系统规则；防 prompt injection |
| 答得对 = 检索好 | 模型可能没用检索结果靠先验答对；必须看引用是否真的指向命中片段 |
