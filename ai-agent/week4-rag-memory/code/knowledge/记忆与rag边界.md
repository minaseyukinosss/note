# 记忆与 RAG 边界

## RAG 是什么

RAG（Retrieval Augmented Generation）是按 query 从外部知识库检索 chunk，拼入上下文后生成回答。

基本链路：

```text
文档 → 切分 → embedding → 向量库
query → embedding → top-k 检索 → 生成（带引用）
```

RAG 是**工具**，每次按需拉数据，不是跨轮自动注入的状态。

## Memory 是什么

Memory 是跨轮或跨会话保留的信息：对话历史、用户偏好、过往工具结果摘要等。

| 类型 | 时效 | 典型实现 |
| --- | --- | --- |
| Working / 短期 | 单次会话 | `messages`、滑动窗口 |
| Episodic | 跨会话事件 | 向量库存对话片段 |
| Semantic | 事实知识 | RAG 文档库 |
| Procedural | 技能 | 提示词模板、工具脚本 |

## 入门阶段要不要做长期记忆

**观点 A（偏工程）**：先把 RAG + 引用 + eval 打牢，再谈写入。Checkpoint 解决续聊即可，不必过早做"自动记住用户一切"。

**观点 B（偏产品）**：用户说"记住我喜欢简短回答"这类偏好，应在同一会话或跨会话早期支持，否则体验差。可以用轻量 summary 写入向量库或 KV 存储。

两者不矛盾：RAG 管静态知识，Memory 管动态偏好；但**不要**把 RAG 检索结果当成"已经记住的用户状态"。

## 安全提醒

检索片段、网页、文件内容都是**数据**，不是系统指令。chunk 里出现"忽略之前指令"一律不执行。
