# Day 12 闭包与作用域：疑问 Q&A

> **背景**：[`02-每日清单.md`](./02-每日清单.md) Day 12（闭包）学习过程中整理的问答；对应练习 [`../code/exercises.py`](../code/exercises.py) 题 8 `make_counter`。复习时可单独阅读，不依赖对话上下文。

## 背景 / 学习目标

- 搞清闭包、`nonlocal`、装饰器、晚绑定坑各自指什么。
- 区分「函数传参」「闭包捕获」「默认参数只求值一次」三个易混话题。
- 区分 mutate（改对象内容）与 rebind（改名字贴在哪）。

---

## Q1：`nonlocal` 是干什么的？

**A**：在**嵌套函数**里，声明「我要改的是外层函数的变量，不是在本层新建同名局部变量」。

```python
def outer():
    count = 0
    def inner():
        nonlocal count   # 改 outer 里的 count
        count += 1
    return inner
```

- **只读**外层变量：不用 `nonlocal`
- **要改**外层变量：必须 `nonlocal`（否则 `count += 1` → `UnboundLocalError`）

| 关键字 | 改哪一层 |
|--------|----------|
| `global` | 模块顶层 |
| `nonlocal` | 直接外层函数（Enclosing） |

---

## Q2：`return counter` 和 `count` 自增是什么关系？

**A**：`return counter` **只把内层函数交出去**，不会改 `count`。

```python
c = make_counter()   # 此时 count 仍是 0
c()                  # 第一次调用才变 1
c()                  # 2
```

- `count` 变 1、2、3 → 因为**反复调用** `c()`，不是因为 `return`
- 不 `return counter` → 外面拿不到函数 → 没人调用 → `count` 一直是 0

---

## Q3：为什么说 `shout(greet)` 里的 `wrapper` 记住了 `greet`，这就是闭包？

**A**：闭包的定义始终一样，只是「外层变量」类型不同。

满足三条即为闭包：

1. 嵌套函数
2. 内层引用外层变量
3. 外层 `return` 内层，外面还在调用

| 例子 | 外层变量 | 内层记住什么 |
|------|----------|--------------|
| `make_counter` | `count`（int） | 数字状态，能自增 |
| `shout` 装饰器 | `func`（function） | 被包装的原函数 |

结构相同，不是两种闭包。

---

## Q4：「内层函数还活着」是什么意思？

**A**：不是外层还在执行，而是**外层 return 之后，内层函数对象仍被变量持有，并且你还会调用它**。

```
make_counter() 执行完  →  外层「关门」
c = make_counter()    →  你拿到「计数器按钮」
c(), c(), c()         →  内层还活着、还在被用
```

正因为内层仍被引用，Python 才保留外层的 `count` / `func`，不让它们被回收。

---

## Q5：装饰器是什么？和闭包什么关系？

**A**：装饰器 = 接受一个函数，返回包装后的新函数。底层就是闭包。

```python
def shout(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@shout
def greet(name):
    return f"Hello, {name}"
# 等价于 greet = shout(greet)
```

`wrapper` 通过闭包记住外层的 `func`，和 `counter` 记住 `count` 是同一套机制。

---

## Q6：默认值只求值一次、晚绑定坑、`make_adder(3)` 怎么区分？

**A**：三个不同问题，不要混。

| 场景 | 共享什么 | 结果 |
|------|----------|------|
| `def bad(acc=[])`（Day 9） | 同一 `def` 的默认 list | 多次调用串台 |
| `[lambda: i for i in range(3)]` | 多个闭包共享**一个** `i` | `[2, 2, 2]` |
| `[lambda i=i: i for i in range(3)]` | 各 lambda 自己的默认参数 | `[0, 1, 2]` |
| 多次 `make_adder(3)` | 每次调用新建独立的 `n` | 不串台 |

口诀：

- **只求值一次** → 哪个 `def` 的默认参数被多次调用共用？
- **晚绑定** → 多个闭包是否绑同一个循环变量？
- **`make_adder`** → 每次调用外层是否新建自己的 `n`？

`lambda i=i: i` 是**故意利用**「默认参数在定义时求值」，给每个 lambda 冻结当时的 `i`。

---

## Q7：「闭包捕获绑定，不是快照」和「传参传引用」是一回事吗？

**A**：**不是。** 这是两个层面。

| 话题 | 在问什么 |
|------|----------|
| **函数传参** | 调用时 `f(obj)` 怎么传 |
| **闭包捕获** | 内层创建时记住了变量还是当时的值 |

闭包语境：

- **绑定**：内层连着外层**变量本身** → 变量后来变了，闭包看到新值
- **快照**：创建时把值存死 → 以后不变

```python
# 绑定
funcs = [lambda: i for i in range(3)]      # [2, 2, 2]

# 快照（默认参数冻结）
funcs = [lambda i=i: i for i in range(3)]  # [0, 1, 2]
```

```python
# 绑定：改外层 x 后，闭包看到新值
def outer():
    x = 10
    def inner():
        return x
    x = 20
    return inner
outer()()   # 20，不是 10
```

## Q8：Python 闭包和 JavaScript 闭包相同吗？

**A**：**概念相同，规则不同。**

| 层级 | 是否相同 |
|------|----------|
| 定义（内层带外层变量出门） | ✅ |
| 晚绑定 | ✅ |
| 语法与作用域规则 | ❌ |

| | Python | JavaScript |
|---|--------|------------|
| 改外层变量 | 要 `nonlocal` / `global` | `let` 可直接改 |
| 循环 + 闭包 | `for` 不建新作用域；用 `i=i` 修复 | `for (let i...)` 每次迭代新 binding |
| 查找顺序 | LEGB | 作用域链 |

---

## Q9：`mutate` 和 `rebind` 什么时候会改变外层？

**A**：看改的是**对象内容**还是**名字贴在哪**。

```python
def mutate(obj):
    obj.append(1)   # mutate → 外面看得见

def rebind(obj):
    obj = []        # rebind → 外面看不见

items = []
mutate(items)   # [1]
rebind(items)   # 还是 [1]
```

| 操作 | 外面会变吗 |
|------|-----------|
| `obj.append(1)` / `obj[k]=v` | ✅ 同一对象，内容变了 |
| `obj = []`（普通参数） | ❌ 只改函数内局部名 |
| `n += 1`（immutable 参数） | ❌ 局部 rebind |
| 嵌套里 `items.append(1)` | ✅ 不用 `nonlocal` |
| 嵌套里 `count += 1` | ❌ 要 `nonlocal count` |
| `return` 新值 + `x = f(x)` | ✅ 调用方自己改绑 |

---

## Q10：能给参数加 `nonlocal`，让 `rebind(items)` 改掉外面的 `items` 吗？

**A**：**不能。**

```python
def rebind(obj):
    nonlocal obj   # ❌ SyntaxError（不是嵌套函数，没有外层 binding）
    obj = []
```

- `nonlocal` 只管**外层嵌套函数**里的变量，不管调用方实参
- Python 没有「按引用传变量名」——参数 `obj = ...` 永远改不了外面的 `items`

**想改调用方的变量：**

```python
# 换对象
items = rebind(items)   # 函数 return 新 list

# 改内容
def fill(obj):
    obj.clear()
    obj.append(99)
fill(items)             # 原地 mutate
```

---

## 总口诀

```
闭包     = 内层函数 + 引用外层变量 + 外层 return 后仍被调用
nonlocal = 嵌套函数里改外层变量（不是改调用方参数）
装饰器   = 闭包的应用，外层变量恰好是 func

mutate   = 改同一对象内容 → 外面看得见
rebind   = 局部名字改贴标签 → 外面看不见（除非 return / nonlocal / global）

晚绑定   = 多个闭包共享同一个变量
修复     = lambda i=i: i 或 make_adder 式工厂

传参 ≠ 闭包捕获 ≠ 默认参数陷阱 —— 三个问题，三套规则
```
