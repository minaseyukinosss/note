## Day 1-2：数据类型与真值

### 学习目标

- 搞懂 `None`、真值规则、`is` vs `==`、可变 vs 不可变。
- 跑通：写出 5 个你觉得反直觉的 Python 行为（如 `[] == False` 为假但 `not []` 为真）。

### 关键观察与结论

#### 1. `[] == False` 吗？`if not []:` 会进分支吗？

**结论**：`[] == False` 为 **False**（类型不同，空列表不等于布尔 `False`）；但 `if not []:` **会进分支**（空列表是假值）。`==` 比的是值是否相等，真值判断看的是 truthiness，不是一回事。`if not x:` 时，`[]`、`{}`、`""`、`0`、`None`、`False` 都会当假。

#### 2. `a = [1]; b = a; b.append(2)`，`a` 变了吗？为什么？

**结论**：**`a` 变了**，变成 `[1, 2]`。因为 `b = a` 没有复制 list，只是让 `b` 也指向同一个 list 对象；`list` 是可变类型，`b.append(2)` 会原地修改这个对象，所以 `a` 也跟着变。

#### 3. `1000 is 1000` 和 `a = 1000; b = 1000; a is b` 结果一样吗？

**结论**：`1000 is 1000` 通常为 `True`（小整数缓存）。同一行 `a = 1000; b = 1000; a is b` 也可能为 `True`（常量复用）；但 `a = int("1000"); b = int("1000"); a is b` 通常为 `False`（运行时各自创建）。`==` 比较值；`is` 比较是否同一对象。比较数值用 `==`，`is` 主要用于 `x is None`。

### 反直觉行为（目标 5 个，Day 1-2 逐步补）

1. `[] == False` 为假，但 `not []` 为真
2. 同一行 `a = 1000; b = 1000; a is b` 可能为真，分开写或用 `int("1000")` 通常为假
3. `b.append(2)` 后 `a` 也变了（同一 list 对象被原地修改）
4. `return name, age` 实际返回的是 tuple，不是两个独立值

## Day 3：list / tuple + 解包

### 学习目标

- 熟练解包（含 `*rest` 收集剩余元素）、函数多返回值。
- 能说清 list / tuple 的区别及 tuple 能当 dict key 的原因。

### 关键观察与结论

#### 1. `a, b, *rest = [1, 2, 3, 4]` 解包；tuple 为什么能当 dict key？

**结论**：`a=1`，`b=2`，`rest=[3, 4]`（`*rest` 把剩余元素收进一个 **list**）。`dict` 的 key 必须可哈希；`tuple` 不可变，可以当 key；`list` 可变，不能当 key（`TypeError: unhashable type: 'list'`）。

#### 2. `first, *mid, last = range(5)`，`mid` 是什么？

**结论**：`first=0`，`mid=[1, 2, 3]`，`last=4`。`*mid` 收的是中间所有元素，类型是 list。

#### 3. `return name, age` 和 tuple / list 分别什么时候用？

**结论**：`return name, age` 实际返回 **tuple** `("Alice", 25)`，调用方用 `n, a = f()` 解包。**tuple**：不可变，固定结构、多返回值、当 dict key。**list**：可变，会增删改的序列（如 Agent 里的 `messages`）。

## Day 4-7：切片 / dict / set / 推导式

### 学习目标

- 熟练切片、dict / set 惯用法、推导式。

### 关键观察与结论

#### 1. `xs[-3:]` 取最近 3 条；`xs[::-1]` 反转——切片三个参数 `[start:stop:step]` 分别控制什么？

**结论**（以 `xs = [0, 1, 2, 3, 4, 5]` 为例）：`xs[-3:]` → `[3, 4, 5]`（从倒数第 3 个到末尾，取最近 3 个）；`xs[::-1]` → `[5, 4, 3, 2, 1, 0]`（整表反转，`step=-1`）；`xs[::2]` → `[0, 2, 4]`（从头到尾每隔一个取一个）。
三参数：`start` 从哪开始（**含**），`stop` 到哪结束（**不含**），`step` 步长；省略则用默认值。切片不会越界，`xs[-100:]` 有多少取多少。

#### 2. `d.get(k, default)` vs `d[k]` 的区别，什么时候必须用前者？

**结论**：key 存在时，`d[k]` 和 `d.get(k, default)` 都返回值。key 不存在时：`d[k]` 抛 `KeyError`；`d.get(k)` 返回 `None`；`d.get(k, default)` 返回 `default`。**必须用 `.get`**：解析 API 响应、读配置等字段可能缺失的场景（如 `response.get("temperature", 0.7)`）。**用 `d[k]`**：key 必须存在，缺了说明程序逻辑有问题，应该报错。

#### 3. list 的 `in` 和 set 的 `in` 复杂度差别？Agent 里「已访问集合」为什么用 set？

**结论**：**list 的 `in`** 是 O(n)，要遍历每个元素。**set 的 `in`** 平均 O(1)，哈希查找。`set(xs)` 自动去重。Agent 里维护 `visited_urls`、`called_tools` 等集合，会高频 `if x in visited`，用 set 比 list 快得多。

#### 4. 推导式 `[f(x) for x in xs if cond(x)]` 和普通 `for` 循环相比，可读性差别在哪？

**结论**：两者功能等价，但适用场景不同。推导式适合「单一目标的过滤 + 转换」，写法紧凑、意图集中（如 `contents = [m["content"] for m in messages if m["role"] == "user"]`）。普通 `for` 循环在逻辑分支多、步骤多（日志、异常处理、多次修改）时更清晰。经验规则：**简单转换优先推导式，复杂流程优先 `for` 循环**。

## Day 8：默认参数 + 关键字参数

### 学习目标

- 分清位置参数 vs 关键字参数；理解 `*` 后强制关键字参数的用途。

### 关键观察与结论

#### 1. `def f(a, b=1, *, c)` 里 `*` 后面的参数有什么限制？

**结论**：`*` 之后的参数**只能用关键字传**，不能用位置。`f(1, c=3)` ✅；`f(1, 2, 3)` ❌（`c` 不能用位置传）。`*` 前的 `b=1` 是默认参数，可省略或用位置/关键字传。

#### 2. 强制关键字参数对"清晰的工具函数接口"有什么好处？

**结论**：
1. 调用时必须写参数名（如 `temperature=0.7`），代码自解释，不用查函数签名猜位置。
2. 多个同类型参数（`int`、`str`）时避免传反，Agent 里 `model`、`temperature`、`max_tokens` 这类参数尤为需要。
3. 以后给函数加参数时，已有 `keyword=...` 调用不受影响，接口演进更安全。

## Day 9：可变默认参数陷阱

### 学习目标

- 复现 `def f(x, cache=[])` 陷阱；掌握 `None` 哨兵写法。

### 关键观察与结论

#### 1. `def bad(x, acc=[])` 连续调 3 次，输出是什么？为什么？

**结论**：`bad(1)` → `[1]`，`bad(2)` → `[1, 2]`，`bad(3)` → `[1, 2, 3]`——不是各自独立的 list。默认参数 `[]` 在**函数定义时**只创建一次，存入 `__defaults__`；所有省略 `acc` 的调用共享同一对象，`.append` 原地修改会跨调用累积。

#### 2. 正确写法是什么？

**结论**：用 `None` 作哨兵，在函数体内按需新建：

```python
def append_log(msg, logs=None):
    if logs is None:
        logs = []
    logs.append(msg)
    return logs
```

`None` 是不可变单例，安全；可变容器（`[]`、`{}`）绝不做默认值。

#### 3. 这在 Agent 状态共享里会怎么埋 bug？

**结论**：`def run_tool(name, history=[])` 会让不同请求/会话共享同一份 `history`，出现上一轮 tool 调用泄漏到下一轮、多用户数据串台。规则：**默认参数永远不用 `[]` / `{}` / `set()`**。

## Day 10：`*args` / `**kwargs`

### 学习目标

- 理解定义处收集（`*args`→tuple、`**kwargs`→dict）与调用处展开（`*list`、`**dict`）；能写包装函数透传参数。

### 关键观察与结论

#### 1. `*args` 和 `**kwargs` 分别在定义处、调用处各做什么？

**结论**：
- **定义处**：`*args` 收集多余位置参数 → tuple；`**kwargs` 收集关键字参数 → dict。顺序必须是 `def f(a, *args, **kwargs)`。
- **调用处**：`*items` 把 list/tuple 拆开当位置参数；`**d` 把 dict 拆开当关键字参数。`real(*args, **kwargs)` 即完整透传。

#### 2. `call_with_defaults` 包装函数怎么工作？

**结论**：先检查 `kwargs` 是否缺 `temperature`，缺则补 `0.7`，再 `return func(*args, **kwargs)`。调用方已传 `temperature` 时不覆盖。这是 SDK / Agent 框架里「注入默认配置 + 透传」的标准模式。

#### 3. `lambda **k: k` 是什么？测试里为什么用它？

**结论**：等价于 `def f(**k): return k`——把所有关键字参数收进 dict 并返回，当探针函数用。`call_with_defaults(lambda **k: k["temperature"])` 用来验证包装层是否成功注入了 `temperature=0.7`。

#### 4. 框架源码里到处是 `**kwargs`，它解决了什么问题？

**结论**：
1. 参数多且会变，`**kwargs` 一次收全，不用频繁改签名。
2. 包装层 `return real(*args, **kwargs)` 不丢调用方参数。
3. 底层加新参数时旧包装代码不用动。
- **`*args` 的实际地位**：Agent / SDK 里 `**kwargs` 更显眼；`*args` 多在装饰器透传、`func(*args, **kwargs)` 完整转发、`*items` 展开调用里配合使用，日常少单独写，但不能不会。

## Day 11：作用域 LEGB

### 学习目标

- 掌握 LEGB 查找顺序；理解「读 vs 写」对作用域的影响；会用 `global` / `nonlocal`。

### 关键观察与结论

#### 1. LEGB 查找顺序是什么？

**结论**：Python 找变量名按 **L**ocal（当前函数）→ **E**nclosing（外层嵌套函数）→ **G**lobal（模块顶层）→ **B**uiltin（内置如 `len`）从内到外逐级查找，找到即用。

#### 2. 函数内改全局变量不加 `global` 会怎样？

**结论**：`count = count + 1` 会抛 `UnboundLocalError`。因为左边 `count = ...` 让 Python 把 `count` 当 Local 变量，右边读 `count` 时 Local 尚未赋值。**只读** Global 不用声明；**要改** Global 须先写 `global count`。

#### 3. `global` 和 `nonlocal` 分别什么时候用？

**结论**：`global` 声明操作模块顶层变量；`nonlocal` 声明操作外层嵌套函数的变量（闭包计数器用，Day 12 会练）。两者都是「告诉 Python 别在 Local 新建同名变量，我要改外层那个」。

#### 4. LEGB 一句话总结

**结论**：Python 找名字从 Local → Enclosing → Global → Builtin 逐级向外；函数内赋值即创建 Local，改 Global 用 `global`，改外层嵌套变量用 `nonlocal`。
