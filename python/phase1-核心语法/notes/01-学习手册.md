## Day 1-2：数据类型与真值

### 学习目标

- 搞懂 `None`、真值规则、`is` vs `==`、可变 vs 不可变。
- 跑通：写出 5 个你觉得反直觉的 Python 行为（如 `[] == False` 为假但 `not []` 为真）。

### 关键观察与结论

#### 1. `[] == False` 吗？`if not []:` 会进分支吗？

**结论**：`[] == False` 为 **False**（类型不同，空列表不等于布尔 `False`）；但 `if not []:` **会进分支**（空列表是假值）。`==` 比的是值是否相等，真值判断看的是 truthiness，不是一回事。`if not x:` 时，`[]`、`{}`、`""`、`0`、`None`、`False` 都会当假。

#### 2. `a = [1]; b = a; b.append(2)`，`a` 变了吗？为什么？

**结论**：**`a` 变了**，变成 `[1, 2]`。因为 `b = a` 没有复制 list，只是让 `b` 也指向同一个 list 对象；`list` 是可变类型，`b.append(2)` 会原地修改这个对象，所以 `a` 也跟着变。

#### 3. `1000 is 1000` 和 `a = 1000; b = 1000; a is b` 结果一样吗？

**结论**：`1000 is 1000` 通常为 `True`（小整数缓存）。同一行 `a = 1000; b = 1000; a is b` 也可能为 `True`（常量复用）；但 `a = int("1000"); b = int("1000"); a is b` 通常为 `False`（运行时各自创建）。`==` 比较值；`is` 比较是否同一对象。比较数值用 `==`，`is` 主要用于 `x is None`。

### 反直觉行为（目标 5 个，Day 1-2 逐步补）

1. `[] == False` 为假，但 `not []` 为真
2. 同一行 `a = 1000; b = 1000; a is b` 可能为真，分开写或用 `int("1000")` 通常为假
3. `b.append(2)` 后 `a` 也变了（同一 list 对象被原地修改）
4. `return name, age` 实际返回的是 tuple，不是两个独立值

## Day 3：list / tuple + 解包

### 学习目标

- 熟练解包（含 `*rest` 收集剩余元素）、函数多返回值。
- 能说清 list / tuple 的区别及 tuple 能当 dict key 的原因。

### 关键观察与结论

#### 1. `a, b, *rest = [1, 2, 3, 4]` 解包；tuple 为什么能当 dict key？

**结论**：`a=1`，`b=2`，`rest=[3, 4]`（`*rest` 把剩余元素收进一个 **list**）。`dict` 的 key 必须可哈希；`tuple` 不可变，可以当 key；`list` 可变，不能当 key（`TypeError: unhashable type: 'list'`）。

#### 2. `first, *mid, last = range(5)`，`mid` 是什么？

**结论**：`first=0`，`mid=[1, 2, 3]`，`last=4`。`*mid` 收的是中间所有元素，类型是 list。

#### 3. `return name, age` 和 tuple / list 分别什么时候用？

**结论**：`return name, age` 实际返回 **tuple** `("Alice", 25)`，调用方用 `n, a = f()` 解包。**tuple**：不可变，固定结构、多返回值、当 dict key。**list**：可变，会增删改的序列（如 Agent 里的 `messages`）。

## Day 4-7：切片 / dict / set / 推导式

### 学习目标

- 熟练切片、dict / set 惯用法、推导式。

### 关键观察与结论

#### 1. `xs[-3:]` 取最近 3 条；`xs[::-1]` 反转——切片三个参数 `[start:stop:step]` 分别控制什么？

**结论**（以 `xs = [0, 1, 2, 3, 4, 5]` 为例）：`xs[-3:]` → `[3, 4, 5]`（从倒数第 3 个到末尾，取最近 3 个）；`xs[::-1]` → `[5, 4, 3, 2, 1, 0]`（整表反转，`step=-1`）；`xs[::2]` → `[0, 2, 4]`（从头到尾每隔一个取一个）。
三参数：`start` 从哪开始（**含**），`stop` 到哪结束（**不含**），`step` 步长；省略则用默认值。切片不会越界，`xs[-100:]` 有多少取多少。

#### 2. `d.get(k, default)` vs `d[k]` 的区别，什么时候必须用前者？

**结论**：key 存在时，`d[k]` 和 `d.get(k, default)` 都返回值。key 不存在时：`d[k]` 抛 `KeyError`；`d.get(k)` 返回 `None`；`d.get(k, default)` 返回 `default`。**必须用 `.get`**：解析 API 响应、读配置等字段可能缺失的场景（如 `response.get("temperature", 0.7)`）。**用 `d[k]`**：key 必须存在，缺了说明程序逻辑有问题，应该报错。

#### 3. list 的 `in` 和 set 的 `in` 复杂度差别？Agent 里「已访问集合」为什么用 set？

**结论**：**list 的 `in`** 是 O(n)，要遍历每个元素。**set 的 `in`** 平均 O(1)，哈希查找。`set(xs)` 自动去重。Agent 里维护 `visited_urls`、`called_tools` 等集合，会高频 `if x in visited`，用 set 比 list 快得多。

#### 4. 推导式 `[f(x) for x in xs if cond(x)]` 和普通 `for` 循环相比，可读性差别在哪？

**结论**：两者功能等价，但适用场景不同。推导式适合「单一目标的过滤 + 转换」，写法紧凑、意图集中（如 `contents = [m["content"] for m in messages if m["role"] == "user"]`）。普通 `for` 循环在逻辑分支多、步骤多（日志、异常处理、多次修改）时更清晰。经验规则：**简单转换优先推导式，复杂流程优先 `for` 循环**。

## Day 8：默认参数 + 关键字参数

### 学习目标

- 分清位置参数 vs 关键字参数；理解 `*` 后强制关键字参数的用途。

### 关键观察与结论

#### 1. `def f(a, b=1, *, c)` 里 `*` 后面的参数有什么限制？

**结论**：`*` 之后的参数**只能用关键字传**，不能用位置。`f(1, c=3)` ✅；`f(1, 2, 3)` ❌（`c` 不能用位置传）。`*` 前的 `b=1` 是默认参数，可省略或用位置/关键字传。

#### 2. 强制关键字参数对"清晰的工具函数接口"有什么好处？

**结论**：
1. 调用时必须写参数名（如 `temperature=0.7`），代码自解释，不用查函数签名猜位置。
2. 多个同类型参数（`int`、`str`）时避免传反，Agent 里 `model`、`temperature`、`max_tokens` 这类参数尤为需要。
3. 以后给函数加参数时，已有 `keyword=...` 调用不受影响，接口演进更安全。

## Day 9：可变默认参数陷阱

### 学习目标

- 复现 `def f(x, cache=[])` 陷阱；掌握 `None` 哨兵写法。

### 关键观察与结论

#### 1. `def bad(x, acc=[])` 连续调 3 次，输出是什么？为什么？

**结论**：`bad(1)` → `[1]`，`bad(2)` → `[1, 2]`，`bad(3)` → `[1, 2, 3]`——不是各自独立的 list。默认参数 `[]` 在**函数定义时**只创建一次，存入 `__defaults__`；所有省略 `acc` 的调用共享同一对象，`.append` 原地修改会跨调用累积。

#### 2. 正确写法是什么？

**结论**：用 `None` 作哨兵，在函数体内按需新建：

```python
def append_log(msg, logs=None):
    if logs is None:
        logs = []
    logs.append(msg)
    return logs
```

`None` 是不可变单例，安全；可变容器（`[]`、`{}`）绝不做默认值。

#### 3. 这在 Agent 状态共享里会怎么埋 bug？

**结论**：`def run_tool(name, history=[])` 会让不同请求/会话共享同一份 `history`，出现上一轮 tool 调用泄漏到下一轮、多用户数据串台。规则：**默认参数永远不用 `[]` / `{}` / `set()`**。

## Day 10：`*args` / `**kwargs`

### 学习目标

- 理解定义处收集（`*args`→tuple、`**kwargs`→dict）与调用处展开（`*list`、`**dict`）；能写包装函数透传参数。

### 关键观察与结论

#### 1. `*args` 和 `**kwargs` 分别在定义处、调用处各做什么？

**结论**：
- **定义处**：`*args` 收集多余位置参数 → tuple；`**kwargs` 收集关键字参数 → dict。顺序必须是 `def f(a, *args, **kwargs)`。
- **调用处**：`*items` 把 list/tuple 拆开当位置参数；`**d` 把 dict 拆开当关键字参数。`real(*args, **kwargs)` 即完整透传。

#### 2. `call_with_defaults` 包装函数怎么工作？

**结论**：先检查 `kwargs` 是否缺 `temperature`，缺则补 `0.7`，再 `return func(*args, **kwargs)`。调用方已传 `temperature` 时不覆盖。这是 SDK / Agent 框架里「注入默认配置 + 透传」的标准模式。

#### 3. `lambda **k: k` 是什么？测试里为什么用它？

**结论**：等价于 `def f(**k): return k`——把所有关键字参数收进 dict 并返回，当探针函数用。`call_with_defaults(lambda **k: k["temperature"])` 用来验证包装层是否成功注入了 `temperature=0.7`。

#### 4. 框架源码里到处是 `**kwargs`，它解决了什么问题？

**结论**：
1. 参数多且会变，`**kwargs` 一次收全，不用频繁改签名。
2. 包装层 `return real(*args, **kwargs)` 不丢调用方参数。
3. 底层加新参数时旧包装代码不用动。
- **`*args` 的实际地位**：Agent / SDK 里 `**kwargs` 更显眼；`*args` 多在装饰器透传、`func(*args, **kwargs)` 完整转发、`*items` 展开调用里配合使用，日常少单独写，但不能不会。

## Day 11：作用域 LEGB

### 学习目标

- 掌握 LEGB 查找顺序；理解「读 vs 写」对作用域的影响；会用 `global` / `nonlocal`。

### 关键观察与结论

#### 1. LEGB 查找顺序是什么？

**结论**：Python 找变量名按 **L**ocal（当前函数）→ **E**nclosing（外层嵌套函数）→ **G**lobal（模块顶层）→ **B**uiltin（内置如 `len`）从内到外逐级查找，找到即用。

#### 2. 函数内改全局变量不加 `global` 会怎样？

**结论**：`count = count + 1` 会抛 `UnboundLocalError`。因为左边 `count = ...` 让 Python 把 `count` 当 Local 变量，右边读 `count` 时 Local 尚未赋值。**只读** Global 不用声明；**要改** Global 须先写 `global count`。

#### 3. `global` 和 `nonlocal` 分别什么时候用？

**结论**：`global` 声明操作模块顶层变量；`nonlocal` 声明操作外层嵌套函数的变量（闭包计数器用，Day 12 会练）。两者都是「告诉 Python 别在 Local 新建同名变量，我要改外层那个」。

#### 4. LEGB 一句话总结

**结论**：Python 找名字从 Local → Enclosing → Global → Builtin 逐级向外；函数内赋值即创建 Local，改 Global 用 `global`，改外层嵌套变量用 `nonlocal`。

## Day 12：闭包

> 延伸 Q&A：[`04-闭包与作用域-qa.md`](./04-闭包与作用域-qa.md)

### 学习目标

- 闭包捕获变量 vs 值；`nonlocal` 实战；晚绑定坑。

### 关键观察与结论

#### 1. 什么是闭包？

**结论**：内层函数引用了外层函数的变量，且外层已经 `return` 了内层函数，调用方仍能通过内层函数访问/修改外层那个变量。`make_counter` 是典型的「工厂函数 + 闭包」：`counter` 记住了 `make_counter` 里的 `count`。

#### 2. `nonlocal` 什么时候用？

**结论**：内层函数要**改**外层（Enclosing）变量时必须声明 `nonlocal`；只读外层变量不用。函数内一旦赋值，Python 默认创建 Local 变量；不加 `nonlocal` 时 `count += 1` 会 `UnboundLocalError`。与 Day 11 对照：`global` 改模块顶层，`nonlocal` 改直接外层函数。

#### 3. `return counter` 和 `count` 自增是什么关系？

**结论**：`return counter` 只是把内层函数对象交出去，**不会**改变 `count`；`make_counter()` 执行完时 `count` 仍是 0。`count` 变成 1、2、3 是因为外面反复**调用** `c()` 触发了 `count += 1`。每次 `make_counter()` 调用创建独立的 `count`，两个 counter 互不干扰。

#### 4. 晚绑定坑：闭包捕获的是变量还是值？

**结论**：捕获的是**变量绑定**，不是创建时的快照。`funcs = [lambda: i for i in range(3)]` 三个 lambda 共享同一个 `i`，循环结束后 `i == 2`，所以 `[f() for f in funcs]` 得 `[2, 2, 2]` 而非 `[0, 1, 2]`。修复：`funcs = [lambda i=i: i for i in range(3)]`，默认参数在定义时求值，把当前 `i` 冻结进每个 lambda。

#### 5. 闭包和装饰器的关系

**结论**：装饰器就是闭包的应用——外层接受一个函数，内层包装它并返回新函数，新函数「记住」了被包装的原始函数。`@decorator` 只是语法糖，等价于 `func = decorator(func)`。阶段二学装饰器时，底层就是今天这套闭包机制。

## Day 13：Week 2 综合练习

### 学习目标

- 自加 2 道题，综合运用推导式、`.get`、dict 合并、递归。
- 识别还不熟的知识点，留到 Day 14 复盘。

### 关键观察与结论

#### 1. 按 role 分组消息怎么写？

**结论**：两步——`roles = {m.get("role") for m in messages}` 收集所有 role；`result = {role: [m.get("content") for m in messages if m.get("role") == role] for role in roles}` 分组。条件必须是 `== role`（匹配当前 role），写成 `in roles` 会误把同一层所有 content 塞进每个 key。

#### 2. 扁平化嵌套 dict 的核心思路？

**结论**：`for key, value in d.items()` 遍历当前层；`full_key` 用 `parent_key + sep + key`（顶层 `parent_key` 为空则直接用 `key`）。`isinstance(value, dict)` 为真则递归，用 `result = {**result, **flatten_dict(value, full_key, sep)}` 合并子结果；否则 `result[full_key] = value` 写叶子。`return` 只放在 `for` 循环结束后——循环中 `return` 会跳过后续 sibling key。

#### 3. `{**result, **sub}` 为什么要带上 `**result`？

**结论**：`result` 是当前层的累加器，同一轮 `for` 里可能先处理完一个 key 再处理下一个。若只写 `{**flatten_dict(...)}` 会覆盖之前已收集的键值；`**result` 表示「保留已有 + 拼上本次递归结果」。

### 口头自测参考答案（Day 14 必做）

#### 1. 可变默认参数陷阱

- **现象**：`def f(x, acc=[])` 连续调用，acc 会跨调用累积。
- **原因**：`[]` 在函数定义时创建一次，所有调用共享同一对象。
- **正确写法**：`def f(x, acc=None): acc = acc or []` 或 `if acc is None: acc = []`。
- **Agent 后果**：`history=[]` 默认值导致多会话 tool 调用历史串台。

#### 2. `*args` / `**kwargs`

- **定义处**：`*args` → tuple，`**kwargs` → dict，收多余参数。
- **调用处**：`*items` / `**d` 展开透传。
- **框架价值**：参数多且会变时一次收全；包装层注入默认值后 `return real(*args, **kwargs)` 不丢参数；底层加新参数旧包装不用改。

#### 3. 闭包

- **定义**：内层函数引用外层变量，外层 return 后内层仍能访问/修改。
- **`nonlocal`**：内层要**改**外层变量时必须声明。
- **晚绑定**：循环里 `lambda: i` 捕获同一变量，调用时取最终值；用 `lambda i=i: i` 冻结。
- **与装饰器**：装饰器 = 接受函数、返回包装函数的闭包。

## Day 15：try/except/else/finally

### 学习目标

- 搞清四段各自何时执行；会捕获**具体异常**（如 `ValueError`），不写裸 `except`。
- 跑通：[`../code/exercises.py`](../code/exercises.py) 题 **11** `safe_int`。

### 关键观察与结论

#### 1. `int("abc")` 抛什么异常？怎么友好处理？

**结论**：抛 **`ValueError`**（值不合法，不是类型错——`int(None)` 才是 `TypeError`）。捕获写法：

```python
try:
    n = int("abc")
except ValueError as e:
    print(f"无法转成整数: {e}")  # invalid literal for int() with base 10: 'abc'
```

Agent 场景：解析 LLM 返回的 JSON 字段、读配置里的数字，字段格式不对时用 `try/except ValueError` 兜底，而不是让整个流程崩溃。

#### 2. `try / except / else / finally` 各段何时执行？

**结论**（按顺序）：

| 段 | 何时执行 |
|----|----------|
| `try` | 总是先执行；出异常则跳去匹配的 `except` |
| `except` | **只有** `try` 里抛了**且类型匹配**的异常才执行 |
| `else` | **只有** `try` **没出任何异常**才执行（不是「else 当 catch 不到时」） |
| `finally` | **无论如何都执行**（有异常、没异常、`return` 之前都会跑） |

无异常路径：`try` → `else` → `finally` → 继续后面代码。  
有异常且被捕获：`try`（到出错行）→ `except` → `finally` → 继续。  
有异常且**没**被捕获：`try` → `finally` → 异常继续向上抛。

#### 3. `else` 和 `finally` 分别放什么代码？

**结论**：

- **`else`**：放「**只有 try 成功才该做**」的逻辑——且不想和 `try` 混在同一缩进里时更清晰。典型：解析成功后做后续处理（`result = parse(data)` 放 try，`process(result)` 放 else）。**不要**把可能出错的代码放 else，那应该放 try。
- **`finally`**：放「**无论成败都要做**」的清理——关文件、关连接、释放锁。即使 `try` 里 `return`，`finally` 仍会先执行（但 `finally` 里的 `return` 会覆盖 try/except 的返回值，少用）。

#### 4. 为什么捕获具体异常，不要裸 `except`？

**结论**：

- `except ValueError:` ✅ 只处理「值不合法」，其他 bug（如 `TypeError`、自己忘写的 `NameError`）仍会暴露。
- `except Exception:` ⚠️ 太宽，会吞掉大部分错误，调试困难。
- `except:` ❌ 裸 except 连 `KeyboardInterrupt`（Ctrl+C）都可能拦住，绝对避免。

习惯：**先写你预期的异常类型**，Agent 里常见：`ValueError`、`KeyError`、`json.JSONDecodeError`、`httpx.HTTPError`。

## Day 16：自定义异常 + EAFP

### 学习目标

- 搞懂 **EAFP** 和 **LBYL** 是什么、差在哪（见下文第 1 节）。
- 会定义 `class XxxError(Exception)`；跑通题 **12** `parse_int`。

### 关键观察与结论

#### 1. EAFP 和 LBYL 分别是什么？

这是两种处理「可能出错的操作」的写法。**同一个任务，两种思路：**

| 缩写 | 英文全称 | 中文意思 | 做法 |
|------|----------|----------|------|
| **LBYL** | **L**ook **B**efore **Y**ou **L**eap | **先查再跳**——跳之前先看安不安全 | 先 `if` 判断条件，通过了再操作 |
| **EAFP** | **E**asier to **A**sk for **F**orgiveness than **P**ermission | **先做了再说**——错了再请求原谅 | 直接操作，出异常再 `except` 处理 |

**最简单例子：从 dict 里取 key**

```python
d = {"name": "Alice"}

# LBYL：先查 key 在不在，再取
if "name" in d:
    value = d["name"]
else:
    value = None

# EAFP：直接取，没有就抓 KeyError
try:
    value = d["name"]
except KeyError:
    value = None
```

两种写法结果一样。差别在**习惯**：Python 标准库（`d[k]`、`int(s)`、`json.loads(s)`）设计就是「不对就抛异常」，所以 Python 代码更常写 EAFP。

**再举一个和今天练习相关的：**

```python
# LBYL：先判断字符串能不能转 int（要写很多检查，还不一定准）
s = "42"
if s.isdigit():          # 只能处理非负整数，"-3" 就漏了
    n = int(s)
else:
    raise MalformedLineError(...)

# EAFP：直接转，失败了再处理（Python 推荐）
try:
    n = int(s)
except ValueError as e:
    raise MalformedLineError(...) from e
```

**什么时候用哪个？**

- **Python 项目**：默认 EAFP，尤其调用标准库时。
- **可以 LBYL 的情况**：条件简单且不会和操作重复，比如 `if x is None:` 再往下走。
- **不要混**：同一层逻辑选一种风格，别又 `if key in d` 又 `try/except KeyError` 写两遍。

#### 2. 自定义异常怎么写？

**结论**：继承 `Exception`，类体通常 `pass` 或加 docstring；需要时可 `__init__` 存额外字段。

```python
class MalformedLineError(Exception):
    """日志行格式不合法。"""
```

调用方用 `except MalformedLineError:` 精确捕获「我们定义的格式错误」，与 `ValueError`、`KeyError` 等标准异常区分开。

#### 3. `safe_int` vs `parse_int`：什么时候返回 default，什么时候 raise？

**结论**：

| 函数 | 失败行为 | 适用场景 |
|------|----------|----------|
| `safe_int`（Day 15） | 返回 `default` | 字段可选、缺了用默认值即可 |
| `parse_int`（Day 16） | `raise MalformedLineError` | 字段**必须合法**，坏数据要上报/跳过/计数 |

Day 21 JSONL CLI：`parse_line` 解析失败就 `raise MalformedLineError`，主程序 `except` 后跳过坏行并计数——这就是 raise 版。

#### 4. `raise ... from e` 是什么？

**结论**：包装异常时保留**原因链**，调试时能看到「MalformedLineError ← 原来是 ValueError」。

```python
try:
    return int(s)
except ValueError as e:
    raise MalformedLineError(f"无法解析整数: {s!r}") from e
```

#### 5. 为什么 Python 用异常而不是返回错误码？

**结论**：

1. **成功路径干净**：不用每个函数都 `if err != OK: return`，正常逻辑不被错误分支打断。
2. **错误不会漏**：忘记检查返回值，错误码会静默失败；未捕获的异常会立刻暴露。
3. **类型分层**：`except MalformedLineError` 只处理「格式坏行」，其他 bug 仍会冒泡。
4. **与 EAFP 配套**：标准库 API 不对就抛异常（`dict[k]`、`int(s)`），惯用法是 try/except，而不是 Go 那种 `(value, err)` 元组。
