## 一、判断题（对 / 错，并一句话说明理由）

### A. 阶段综合（M1）

1. 判空应优先写 `if x == False:`，比 `if not x:` 更严谨。
2. `def f(items=[]): items.append(1); return items` 连续两次 `f()` 都会返回 `[1]`。
3. 函数内对传入的 list 执行 `.append`，调用方持有的同一个 list 也会变。
4. `[m["content"] for m in msgs if m["role"] == "user"]` 在 `m` 缺少 `"role"` 时会抛 `KeyError`（与 `m.get` 无关）。

### B. 异常与 EAFP（Day 15–16）

5. `int("abc")` 会抛 `TypeError`。
6. `try` 块没有异常时，会执行 `else` 块。
7. 即使 `try` 里写了 `return`，`finally` 仍会执行（然后再真正返回）。
8. 捕获异常时，写裸 `except:` 比 `except ValueError:` 更符合 Python 习惯。
9. EAFP 典型写法：先 `try: value = d["timeout"]`，再 `except KeyError: value = 30`。
10. `raise MalformedLineError("bad") from e` 的作用之一是保留原始异常链，便于调试。
11. Python 标准库里的 `dict[k]`、`int(s)` 失败时通常抛异常，而不是返回错误码。

### C. 模块、包与 CLI（Day 17–21）

12. 解释器执行到 `import foo` 这一行时，才会加载并执行 `foo.py` 的顶层代码。
13. 同一进程里第二次 `import foo`，会再次完整执行 `foo.py` 顶层（如同第一次）。
14. 用 `python greet.py` 直接跑脚本时，该文件里 `__name__` 的值是 `"__main__"`。
15. 在包内模块里写 `from .parser import parse_line` 时，`.` 表示当前包（如 `logtool`）。
16. 在 `code/` 目录下执行 `python logtool/__main__.py`，与 `python -m logtool` 对相对导入同样安全。
17. `logtool` 项目中，单行 JSON 语法错误应在 `parse_line` 里返回 `None`，由调用方判断，而不是 `raise`。
18. `read_lines` 循环里应只捕获 `MalformedLineError` 来跳过坏行；`KeyError` 等应继续向上抛。
19. CLI 里「文件不存在」类提示放在 `stderr`，统计结果放在 `stdout`，是常见约定。
20. `print(f"{text!r}")` 等价于对 `text` 使用 `repr()` 再格式化。

### 四、简答与手写要点

#### 1. M1 三陷阱（各 2～3 句）

**真值规则**  
Python 在布尔语境里用「假值」判断：`None`、`False`、`0`、`""`、`[]`、`{}` 等在 `if` 里都当假。判空 / 判有无用 `if not x:`，不要用 `x == False`（漏 `None`、空容器，且 `0 == False` 为真易混）。

**可变默认参数**  
`def f(items=[])` 里的 `[]` 在**函数定义时只创建一次**，多次调用共享同一 list，`.append` 会跨调用累积。应写 `items=None`，函数体内 `if items is None: items = []`。

**传参是对象引用**  
传参传的是对象的引用，不是自动深拷贝。对 list、dict 等可变对象原地修改（如 `.append`），调用方持有的同一对象也会变；对 int、str 等不可变对象「重新赋值」不影响外部变量。

#### 2. EAFP 在 `logtool` 里如何分层？

| 层 | 职责 | 异常策略 |
| --- | --- | --- |
| **`parse_line`** | 单行：`strip` → `json.loads` → 必须是 `dict` | 失败 **`raise MalformedLineError`**（可用 `from e` 保留 `JSONDecodeError` 链）；不在此层返回 `None` |
| **`read_lines`** | 读整文件，逐行调用 `parse_line` | **只捕获 `MalformedLineError`**：坏行 `bad_count += 1` 并继续；`KeyError` 等程序 bug 继续向上抛 |
| **`main`** | CLI：取参数 → `read_lines` → `count_by_level` → 打印 | 捕 **`FileNotFoundError`** → stderr + `return 1`；统计结果走 stdout |

**坏行在哪一层跳过**：在 **`read_lines`** 的循环里捕获 `MalformedLineError` 后计数并跳过；`parse_line` 只负责判定「这一行是否合法」并 raise。

#### 3. 手写伪代码

```python
def parse_line(line: str) -> dict:
    text = line.strip()
    if not text:
        raise MalformedLineError("empty line")
    try:
        obj = json.loads(text)
    except json.JSONDecodeError as e:
        raise MalformedLineError(f"invalid JSON: {text!r}") from e
    if not isinstance(obj, dict):
        raise MalformedLineError(
            f"expected JSON object, got {type(obj).__name__}: {text!r}"
        )
    return obj


def count_by_level(records) -> dict[str, int]:
    counts = defaultdict(int)
    for record in records:
        level = record.get("level", "unknown")
        counts[level] += 1
    return dict(counts)
```

#### 4. import 与包

- **为什么说「import 是运行时执行的」？**  
  `import` 是普通语句，解释器**执行到那一行**才加载模块并运行模块顶层代码；同一进程第二次 `import` 同一模块用 `sys.modules` 缓存，不重复执行顶层。

- **为什么 CLI 要用 `python -m logtool` 而不是直接跑 `logtool/__main__.py` 路径？**  
  `-m logtool` 把 `logtool` 当作**包**运行，包内 `from .parser import ...` 才有父包上下文；直接跑文件路径常报 `ImportError: attempted relative import with no known parent package`。

### 五、场景应用题

#### 1. JSONL 日志 CLI

| 模块 | 放什么 | 异常 |
| --- | --- | --- |
| **`parser.parse_line`** | 单行 JSON → `dict`；校验必须是对象 | 语法错 / 非 dict → **`raise MalformedLineError`** |
| **`parser.read_lines`** | `open` 文件、逐行、空行跳过、收集好行 | 只捕 **`MalformedLineError`** 计 bad 并 continue；不捕 `KeyError` |
| **`stats.count_by_level`** | 对已解析的 `records` 按 `level` 计数 | 不碰 IO；缺 `level` 用 `.get(..., "unknown")`，不抛异常 |
| **`__main__.main`** | `sys.argv` / 注入 `argv`、调 `read_lines` → `count_by_level`、打印 | 捕 **`FileNotFoundError`** → `stderr` + **`return 1`**；成功结果 `stdout` + `return 0` |

**产品要求对应**：单行坏 → `read_lines` 跳过；文件不存在 → `main` 明确 stderr 提示且退出码非 0。

#### 2. LLM 调用包装

底层 SDK 参数名、数量常随版本变化。包装层用 `def call_llm(model, **kwargs)` **透传**未知关键字，调用方可写 `temperature=0.2` 等新参数而不用改包装函数签名；包装内可用 `kwargs.setdefault("temperature", 0.7)` 只补默认值，不挡调用方覆盖。若在签名里写死十个参数，SDK 每增一个参数就要改包装层，易漏、难维护。
