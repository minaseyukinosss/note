## 一、判断题（对 / 错，并一句话说明理由）

### A. 阶段综合（M1）

1. 判空应优先写 `if x == False:`，比 `if not x:` 更严谨。
2. `def f(items=[]): items.append(1); return items` 连续两次 `f()` 都会返回 `[1]`。
3. 函数内对传入的 list 执行 `.append`，调用方持有的同一个 list 也会变。
4. `[m["content"] for m in msgs if m["role"] == "user"]` 在 `m` 缺少 `"role"` 时会抛 `KeyError`（与 `m.get` 无关）。

### B. 异常与 EAFP（Day 15–16）

5. `int("abc")` 会抛 `TypeError`。
6. `try` 块没有异常时，会执行 `else` 块。
7. 即使 `try` 里写了 `return`，`finally` 仍会执行（然后再真正返回）。
8. 捕获异常时，写裸 `except:` 比 `except ValueError:` 更符合 Python 习惯。
9. EAFP 典型写法：先 `try: value = d["timeout"]`，再 `except KeyError: value = 30`。
10. `raise MalformedLineError("bad") from e` 的作用之一是保留原始异常链，便于调试。
11. Python 标准库里的 `dict[k]`、`int(s)` 失败时通常抛异常，而不是返回错误码。

### C. 模块、包与 CLI（Day 17–21）

12. 解释器执行到 `import foo` 这一行时，才会加载并执行 `foo.py` 的顶层代码。
13. 同一进程里第二次 `import foo`，会再次完整执行 `foo.py` 顶层（如同第一次）。
14. 用 `python greet.py` 直接跑脚本时，该文件里 `__name__` 的值是 `"__main__"`。
15. 在包内模块里写 `from .parser import parse_line` 时，`.` 表示当前包（如 `logtool`）。
16. 在 `code/` 目录下执行 `python logtool/__main__.py`，与 `python -m logtool` 对相对导入同样安全。
17. `logtool` 项目中，单行 JSON 语法错误应在 `parse_line` 里返回 `None`，由调用方判断，而不是 `raise`。
18. `read_lines` 循环里应只捕获 `MalformedLineError` 来跳过坏行；`KeyError` 等应继续向上抛。
19. CLI 里「文件不存在」类提示放在 `stderr`，统计结果放在 `stdout`，是常见约定。
20. `print(f"{text!r}")` 等价于对 `text` 使用 `repr()` 再格式化。

## 六、复盘总结（结业易错点）

| 知识点 | 易错表现 | 正确理解 |
| --- | --- | --- |
| 假值 vs 判空 | 用 `== False` 判空 | 用 `if not x:`；区分 `0 == False` 与 `[] == False` |
| 异常类型 | 以为 `int("abc")` 是 `TypeError` | 是 `ValueError` |
| `else` / `finally` | 在 `else` 里写可能抛错的代码 | `else` 放 try 成功后的逻辑；资源清理放 `finally` |
| EAFP vs 坏行 | 在 `parse_line` 里吞掉异常返回 None | 解析失败 `raise`；文件级在 `read_lines` 选择性捕获 |
| 相对导入 | 直接跑 `__main__.py` 路径 | 在 `code/` 下 `python -m logtool` |
| CLI 输出 | 错误与结果都用 `print()` | 错误走 `stderr`，结果走 `stdout`；失败 `return 1` |
| `.get` 缺字段 | 用 `d[k] or default` 当万能 | 缺 key 时 `d[k]` 仍 KeyError；用 `d.get(k, default)` |
