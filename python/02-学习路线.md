# 学习路线：四阶段详解

> 每个知识点后面都标了**「Agent 用途」**——学任何东西前先问一句"这在 Agent 项目里干什么用"，学不动的先跳过。
> 完整的按天/按周计划见 [03-90天计划](./03-90天计划.md)。

## 总原则

1. **只补差异**：变量、循环、条件这类通用编程概念你已经会，跳过；把精力放在 Python 特有的语法、惯用法和陷阱上。
2. **代码验证**：每个知识点必须写一段能跑的代码，光看会忘。
3. **用途锚定**：每学一个特性，都对应到"读源码时会遇到"或"写 Agent 时要用"。
4. **顺序不可乱**：地基（类型/异常）→ 抽象（OOP/装饰器）→ 工程 → 专项。

---

## 阶段一：Python 核心语法强化（Day 1-21）

> 目标：补齐数据结构和函数设计的**惯用法**，跳过"什么是变量"这种内容。重点在 Python 特有的简洁写法和陷阱。

| 知识点 | 学习重点 | Agent 用途 |
| --- | --- | --- |
| 数据类型 | `None` 与真值规则、不可变 vs 可变、`is` vs `==` | 判断 LLM 返回是否为空、状态比较 |
| list / tuple | tuple 不可变、可做 dict key、解包 `a, *rest = xs` | 存 messages、返回多值 |
| dict | `.get(k, default)`、`dict` 合并 `{**a, **b}`、`.items()` | 解析 `tool_calls`、构造请求体 |
| set | 去重、交并差、成员判断 O(1) | 去重检索结果、已访问工具集合 |
| 切片 | `xs[start:stop:step]`、负索引、`xs[::-1]` | 截断上下文、取最近 N 条消息 |
| 推导式 | list/dict/set 推导、条件过滤、嵌套 | 批量转换 chunk、过滤消息 |
| 函数设计 | 默认参数、关键字参数、返回多值 | 工具函数、清晰的接口 |
| 参数传递 | 传对象引用、可变对象就地修改陷阱 | 传 messages 时避免意外修改 |
| `*args` / `**kwargs` | 收集与透传、`func(**config)` | **读框架源码必备**，到处是 kwargs 透传 |
| 作用域 | LEGB 规则、`global` / `nonlocal`、闭包捕获 | 闭包做回调、避免作用域 bug |
| 异常处理 | `try/except/else/finally`、自定义异常、EAFP 风格 | LLM/网络调用鲁棒性 |
| 模块与包 | `import` 机制、`__init__.py`、相对导入、循环导入 | 组织 Agent 项目代码 |

**阶段产出**：一个纯标准库的命令行小工具（如 JSONL 日志分析器），用到推导式、异常、模块拆分。

## 阶段二：Python 高级特性（Day 22-45）

> 目标：吃透让 Python 代码"高级"的特性。**这一阶段直接决定你能不能读懂框架源码**。

| 知识点 | 学习重点 | Agent 用途 |
| --- | --- | --- |
| 面向对象 | `self`、`__init__`、类属性 vs 实例属性、`@classmethod`/`@staticmethod` | 封装 Agent、Tool、Memory 类 |
| 继承 / 多态 | 单继承、多继承 MRO、`super()`、鸭子类型 | 理解框架继承链（BaseModel → 你的模型） |
| 抽象基类 / Protocol | `ABC` + `@abstractmethod`、`Protocol` 结构化子类型 | 框架核心抽象（`Runnable`、`BaseChatModel`） |
| 魔术方法 | `__call__`、`__repr__`、`__eq__`、`__enter__/__exit__`、`__iter__` | 理解 `agent(input)` 为何可调用 |
| 装饰器 | 函数装饰器、带参装饰器、`functools.wraps`、类装饰器 | `@tool`、`@app.post`、重试、缓存 |
| 闭包 | 变量捕获、`nonlocal`、装饰器的底层 | 回调、middleware、工厂函数 |
| 生成器 | `yield`、惰性求值、`yield from` | **LLM streaming 逐 token 输出** |
| 迭代器 | 迭代器协议、`iter()`/`next()`、`itertools` | 自定义可迭代对象、流式管道 |
| 上下文管理器 | `with`、`__enter__/__exit__`、`contextlib.contextmanager` | client 生命周期、trace span、资源清理 |
| dataclass | `@dataclass`、`field`、`frozen`、默认值 | 轻量状态建模（不需要校验时） |
| typing | 泛型 `list[T]`、`Optional`、`Union`/`|`、`Callable`、`TypedDict`、`Literal`、`Protocol` | **读源码的前提**、工具签名、schema 生成 |

**阶段产出**：手写一个迷你版"可组合调用链"（模仿 LCEL 的 `|` 操作符思路），用到魔术方法 + 装饰器 + typing。

## 阶段三：Python 工程能力（Day 46-66）

> 目标：从"会写脚本"到"会做项目"。让你的 Agent 代码有结构、可配置、可测试、可维护。

| 知识点 | 学习重点 | Agent 用途 |
| --- | --- | --- |
| 项目目录设计 | `src/` 布局、包划分、入口 `__main__.py` | Agent 项目分层（core / tools / config） |
| 虚拟环境 | venv 原理、为什么要隔离 | 每个 Agent 项目独立依赖 |
| uv | `uv init`/`add`/`run`/`sync`、替代 pip+venv+poetry | **现代首选**，快且统一 |
| 依赖管理 | `pyproject.toml`、`uv.lock`、依赖分组（dev/prod） | 锁定框架版本，可复现 |
| 配置管理 | `pydantic-settings`、`.env`、分环境配置 | 管理 API Key、模型名、超时 |
| 日志系统 | `logging` 模块、logger 层级、结构化日志、`rich` | Agent trace、调试工具调用 |
| 单元测试 | pytest、fixture、参数化、mock、`monkeypatch` | 测工具函数、mock LLM 响应 |
| 代码质量 | ruff（lint+format）、pyright（类型）、pre-commit | 保持工程级代码质量 |
| 编码规范 | PEP 8、命名约定、docstring（Google 风格） | 写出可读、可维护的代码 |

**阶段产出**：把阶段二的项目重构成标准 `uv` 工程：`pyproject.toml` + 配置 + 日志 + 测试 + 通过 ruff/pyright。

---

## 阶段四：AI Agent 开发专项能力（Day 67-90）

> 目标：把前三阶段的能力用到真实 Agent 技术栈上，并开始读框架源码。

| 知识点 | 学习重点 | Agent 用途 |
| --- | --- | --- |
| async / await | 协程、`await`、事件循环要显式启动 | 异步调用 LLM |
| asyncio | 事件循环、`gather`、`create_task`、超时、并发控制 | 并发调多个工具/LLM、限流 |
| HTTP 请求 | `httpx`（sync + async）、超时、重试、流式 | 调 LLM API、外部工具 |
| API 封装 | 封装 client、错误处理、重试（tenacity） | 稳定的 LLM 调用层 |
| JSON 处理 | `json` 模块、嵌套解析、`json.loads` 容错 | 解析 tool_calls、结构化输出 |
| 数据模型设计 | 用 Pydantic 建模领域对象 | Agent State、Message、ToolCall |
| Pydantic v2 | `BaseModel`、校验器、`model_validate`、`Field`、序列化 | **结构化输出、工具 schema、配置** |
| FastAPI | 路由、依赖注入、`async` 端点、SSE 流式 | 把 Agent 暴露成 API 服务 |
| 读框架源码 | LangChain Core（Runnable/LCEL）、LlamaIndex | 理解设计模式、能改能扩展 |
| Agent 设计模式 | 注册表、策略、责任链、middleware、事件流 | 设计自己的 Agent 框架 |

**阶段产出**：一个完整的异步 Agent 服务——FastAPI 暴露接口、Pydantic 定义 schema、httpx 异步调 LLM、流式返回、有测试和日志。
